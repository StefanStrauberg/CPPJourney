# 01.2 Переменные и фундаментальные типы

> [!abstract] О чём урок
> - что такое переменная с точки зрения памяти;
> - целые типы, их размеры и диапазоны; почему `long` в Windows всего 4 байта;
> - числа с плавающей точкой: почему `0.1 + 0.2 != 0.3` и почему в играх `float`, а не `double`;
> - шесть способов инициализировать переменную и какой выбрать;
> - литералы, `auto`, `const` и `constexpr`;
> - как число лежит в памяти байт за байтом.

## Переменная — это именованный кусок памяти

```cpp
int health = 100;
```

Эта строка делает три вещи:
1. **Выделяет** место в памяти под значение типа `int` (4 байта).
2. **Связывает** это место с именем `health`.
3. **Записывает** туда значение `100`.

**Тип** определяет:
- **сколько байт** занимает значение;
- **как интерпретировать** эти байты (одни и те же 4 байта могут быть целым числом, дробным числом или четырьмя символами);
- **какие операции** допустимы (числа можно делить, строки нельзя).

C++ — язык со **статической типизацией**: тип переменной известен при компиляции и не меняется. Как в C# и Go, в отличие от Python.

## Фундаментальные типы

Вот размеры типов в MSVC под Windows x64. Я получил их программой с оператором `sizeof`, который возвращает размер типа в байтах:

| Тип | Размер | Диапазон / назначение |
|---|---|---|
| `bool` | 1 байт | `true` или `false` |
| `char` | 1 байт | символ / маленькое целое: −128…127 |
| `short` | 2 байта | −32 768…32 767 |
| `int` | 4 байта | −2 147 483 648…2 147 483 647 (≈ ±2,1 млрд) |
| `long` | **4 байта** | как `int` (в Windows!) |
| `long long` | 8 байт | ≈ ±9,2 × 10¹⁸ |
| `float` | 4 байта | дробное, ~7 значащих цифр |
| `double` | 8 байт | дробное, ~15–16 значащих цифр |
| `long double` | 8 байт | в MSVC то же самое, что `double` |
| `wchar_t` | 2 байта | «широкий» символ (UTF-16 в Windows) |

У каждого целого типа есть **беззнаковый** (`unsigned`) вариант: тот же размер, но только неотрицательные значения, и вдвое больший максимум. Например, `unsigned int`: 0…4 294 967 295.

> [!warning] Стандарт не фиксирует размеры
> Стандарт C++ гарантирует только **минимальные** размеры и порядок: `char` ≤ `short` ≤ `int` ≤ `long` ≤ `long long`, при этом `int` не меньше 16 бит, а `long` не меньше 32. Остальное решает платформа. Самый известный пример: `long` в Windows занимает **4 байта**, а в Linux и macOS (64 бита) — **8**. Код, который рассчитывает на 8-байтовый `long`, молча сломается при переносе на Windows.

> [!compare] Размеры в других языках
> | C++ (MSVC x64) | C# | Go |
> |---|---|---|
> | `int` (4) | `int` (4) | `int32` (в Go `int` — 8 байт на 64-битной платформе!) |
> | `long long` (8) | `long` (8) | `int64` |
> | `unsigned char` (1) | `byte` (1) | `uint8` / `byte` |
> | `float` (4) | `float` (4) | `float32` |
> | `double` (8) | `double` (8) | `float64` |
>
> Осторожно с названиями: `long` в C# — это 8 байт, а `long` в C++ под Windows — 4.

### Типы фиксированного размера

Когда размер важен (файлы, сеть, упаковка данных), используй типы из заголовка `<cstdint>`, у которых размер записан прямо в имени:

| Тип | Размер | Беззнаковый |
|---|---|---|
| `std::int8_t` | 1 байт | `std::uint8_t` |
| `std::int16_t` | 2 байта | `std::uint16_t` |
| `std::int32_t` | 4 байта | `std::uint32_t` |
| `std::int64_t` | 8 байт | `std::uint64_t` |

И ещё один важный тип: **`std::size_t`** — беззнаковое целое, достаточное для хранения размера любого объекта в памяти. На x64 это 8 байт. Его возвращает `sizeof`, и он используется для размеров и индексов в стандартной библиотеке.

> [!engine] Короткие имена типов в движках
> Писать `std::uint32_t` долго, поэтому почти каждый движок заводит короткие псевдонимы:
> ```cpp
> using u8  = std::uint8_t;
> using u32 = std::uint32_t;
> using i32 = std::int32_t;
> using f32 = float;
> ```
> В Unreal Engine это `uint8`, `int32`, `uint64`, в других движках `u8`/`u32`/`f32`. Мы заведём такие же псевдонимы в Ember. Слово `using` здесь объявляет **псевдоним типа**, подробнее в модуле 02.

### `char` — это число

`char` — однобайтовое **целое**, которое по традиции используется для символов. Символ в одинарных кавычках — это просто его код:

```cpp
#include <print>

int main() {
    char letter = 'A';
    int code = letter;           // 65: код символа 'A' в ASCII
    char next = letter + 1;      // 'B'
    std::println("{} {} {}", letter, code, next);   // A 65 B
}
```

> [!warning] `char` и кириллица
> Один `char` — один **байт**. Латинская буква в UTF-8 занимает один байт, а кириллическая — **два**. Поэтому `char c = 'Ж';` не сработает: «Ж» в один байт не помещается. Русский текст хранится в строках (`std::string`), где буква занимает два `char`. Подробнее в [[01.6 Ввод, вывод, строки и случайность]].

> [!deep] Под капотом: знаковый ли `char`?
> Стандарт оставляет это на усмотрение платформы: `char` может быть знаковым (−128…127) или беззнаковым (0…255). В MSVC он **знаковый**. Поэтому для «сырых байтов» (содержимое файла, пиксели) используют `unsigned char` или `std::uint8_t`, где диапазон 0…255 гарантирован, или специальный тип `std::byte`.

### `bool`

```cpp
bool isAlive = true;
bool hasKey = false;
```

`bool` занимает целый байт, хотя хранит один бит информации: процессор не умеет адресовать отдельные биты, минимальная адресуемая единица — байт. При преобразовании в число `true` даёт `1`, `false` — `0`. Обратно: `0` превращается в `false`, **любое другое** число — в `true`.

## Числа с плавающей точкой

```cpp
float speed = 5.5f;      // суффикс f: литерал типа float
double gravity = 9.81;   // без суффикса: литерал типа double
```

`float` и `double` хранят числа в формате **IEEE 754**, как научную запись в двоичной системе: знак × мантисса × 2^порядок.

| | `float` | `double` |
|---|---|---|
| Размер | 4 байта (32 бита) | 8 байт (64 бита) |
| Знак / порядок / мантисса | 1 / 8 / 23 бита | 1 / 11 / 52 бита |
| Значащих десятичных цифр | ~7 | ~15–16 |
| Максимум | ~3,4 × 10³⁸ | ~1,8 × 10³⁰⁸ |

### Почему 0.1 + 0.2 != 0.3

```cpp
#include <print>

int main() {
    std::println("{}", 0.1 + 0.2);          // 0.30000000000000004
    std::println("{}", 0.1 + 0.2 == 0.3);   // false
    std::println("{:.20f}", 0.1);           // 0.10000000000000000555
}
```

Число 0,1 в двоичной системе — бесконечная дробь (как 1/3 = 0,333… в десятичной). В 52 бита мантиссы она не помещается, и хранится **ближайшее** представимое число, чуть больше 0,1. Ошибки округления складываются, и результат отличается от 0,3 в 17-м знаке.

> [!warning] Не сравнивай дробные числа через `==`
> Вместо `a == b` проверяй, что числа **достаточно близки**:
> ```cpp
> std::abs(a - b) < 0.0001f   // std::abs из <cmath>
> ```
> Подходящая точность (эпсилон) зависит от задачи. Для координат в игровом мире обычно хватает 0,0001–0,001.

### Точность зависит от величины числа

У `float` примерно 7 значащих цифр **в сумме**. Чем больше число, тем меньше цифр остаётся на дробную часть. Шаг между соседними представимыми значениями `float`:

| Значение | Шаг до следующего `float` |
|---|---|
| 1 | 0,00000012 |
| 1 000 | 0,00006 |
| 100 000 | 0,0078 |
| 10 000 000 | 1,0 |
| 16 777 216 (2²⁴) | 2,0: `16777216.0f + 1.0f == 16777216.0f` истинно! |

> [!engine] Почему в играх `float`, а не `double`, и чем это грозит
> **Почему `float`.** Вдвое меньше памяти, значит вдвое больше данных помещается в кэш процессора. SIMD-инструкции обрабатывают за раз вдвое больше `float`, чем `double`. Видеокарты считают в основном во `float`. Семи значащих цифр хватает для позиций, скоростей и цветов.
>
> **Чем грозит.** Если единица мира — метр, то на расстоянии 100 км от начала координат шаг `float` уже ~8 мм, а на 10 000 км — целый метр. Персонаж вдали от центра карты начинает «дрожать», физика ломается. Известные решения:
> - **плавающее начало координат** (floating origin): когда игрок уходит далеко, весь мир сдвигается так, чтобы игрок снова оказался около нуля (так делала Kerbal Space Program);
> - **`double` для позиций**: Unreal Engine 5 перешёл на `double` в мировых координатах (Large World Coordinates), оставив `float` для всего остального.

### Бесконечность и NaN

Деление дробного числа на ноль **не** является неопределённым поведением: IEEE 754 даёт специальные значения.

- `1.0 / 0.0` = `inf` (бесконечность);
- `0.0 / 0.0` или `inf - inf` = `nan` (Not a Number, «не число»).

У NaN странное свойство: **он не равен ничему, даже самому себе**. `nan == nan` даёт `false`. Если в твоих вычислениях появился NaN, он «заражает» всё, к чему прикасается: любая арифметика с NaN даёт NaN. Классический баг в игре: объект исчез с экрана, потому что его позиция стала NaN из-за деления на нулевую длину вектора.

> [!ub] А вот целочисленное деление на ноль — UB
> `int x = 5 / 0;` — неопределённое поведение. На процессорах x86 программа обычно падает с исключением *Integer division by zero*, но рассчитывать на это нельзя.

## Инициализация

В C++ (исторически) несколько способов дать переменной начальное значение:

```cpp
int a = 5;      // копирующая инициализация: привычный вид
int b(5);       // прямая инициализация: как вызов конструктора
int c{5};       // инициализация фигурными скобками (C++11)
int d = {5};    // то же, со знаком =
int e{};        // фигурные скобки без значения: ноль
int f;          // БЕЗ инициализации: мусор!
```

> [!ub] Неинициализированная переменная
> `int f;` внутри функции **не** обнуляется. В ней лежит то, что осталось в памяти от предыдущих вызовов (в Debug-сборке MSVC — `0xCCCCCCCC`, в Release — что угодно). **Чтение** такой переменной до первого присваивания — неопределённое поведение. Ты уже видел это в [[Практикум 00 — Инструменты#Задание 4. Детектив — волны врагов ⭐⭐|практикуме 00]].
>
> Правило курса: **всегда инициализируй переменную при объявлении**.

> [!compare] В других языках
> - **C#**: локальную переменную нельзя прочитать до присваивания: это ошибка компиляции.
> - **Go**: любая переменная автоматически получает нулевое значение.
> - **C++**: неинициализированная локальная переменная содержит мусор. Компилятор лишь предупреждает (`C4700`), и то не всегда может это заметить.
>
> Почему C++ не обнуляет переменные? Опять ради скорости: если ты сразу перезапишешь значение, обнуление было бы лишней работой. Для массива на миллион элементов это заметно.

### Сужающие преобразования

Главное отличие фигурных скобок: они **запрещают сужение** (narrowing), то есть потерю данных при инициализации:

```cpp
#include <print>

int main() {
    double damage = 37.9;
    int a = damage;     // компилируется (с предупреждением): a = 37, дробная часть потеряна
    int b{damage};      // ошибка компиляции: сужающее преобразование double → int
    std::println("{} {}", a, b);
}
```

Компилятор предупреждает о первой строке и отказывается собирать вторую:
```
warning C4244: инициализация: преобразование "double" в "int", возможна потеря данных
error C2397: Преобразование из "double" в "int" требует сужающего преобразования.
```

**Какой способ выбирать?** В курсе используем `=` для простых значений (`int health = 100;`) и `{}`, когда нужна защита от сужения или «нулевое» значение (`int score{};`). Главное — никогда не оставлять переменную без значения.

## Литералы

**Литерал** — значение, записанное прямо в коде.

| Литерал | Тип | Пример |
|---|---|---|
| Целое | `int` | `42`, `-7` |
| С суффиксом `u` | `unsigned int` | `42u` |
| С суффиксом `ll` | `long long` | `42ll` |
| С суффиксом `ull` | `unsigned long long` | `42ull` |
| Шестнадцатеричное | `int` | `0xFF` (= 255) |
| Двоичное | `int` | `0b1010` (= 10) |
| С разделителями | `int` | `1'000'000` (апострофы для читаемости) |
| Дробное | `double` | `3.14`, `1e-6`, `2.5e3` (= 2500) |
| Дробное с `f` | `float` | `3.14f` |
| Символ | `char` | `'A'`, `'\n'` |
| Строка | массив `char` | `"текст"` |
| Логическое | `bool` | `true`, `false` |

> [!warning] Ловушка восьмеричной системы
> Целое число, которое начинается с нуля, записано в **восьмеричной** системе: `010` — это **8**, а не 10. Никогда не выравнивай числа в коде нулями: `int codes[] = {001, 010, 100};` содержит 1, 8 и 100.

> [!warning] `f` для `float`
> `float speed = 0.1;` — литерал `0.1` имеет тип `double`, и при записи во `float` он будет округлён (с предупреждением компилятора о потере точности). Пиши `0.1f`. В выражениях вроде `speed * 0.5` без `f` всё выражение посчитается в `double`, а потом обрежется до `float`: лишняя работа.

## `auto`: вывод типа

Тип переменной можно не писать: компилятор выведет его из инициализатора.

```cpp
auto lives = 3;          // int
auto speed = 5.5f;       // float
auto gravity = 9.81;     // double
auto big = 5'000'000'000ll;  // long long
auto isAlive = true;     // bool
```

Тип выводится **один раз при компиляции** и дальше не меняется: это всё ещё статическая типизация. `auto` — не `var` из JavaScript и не динамический тип Python.

> [!compare] Аналоги
> `auto x = 5;` ≈ C# `var x = 5;` ≈ Go `x := 5`.

> [!warning] Ловушка: `auto` и строки
> `auto name = "Doomguy";` даёт **не** `std::string`, а `const char*` (указатель на массив символов, модуль 03). Для строки пиши тип явно: `std::string name = "Doomguy";`.

Когда использовать `auto`? Когда тип очевиден из правой части или когда он длинный и неинтересный (в модуле 06 встретятся типы вроде `std::unordered_map<std::string, std::vector<Enemy>>::const_iterator`). Для простых чисел лучше писать тип явно: `int`, `float`, сразу видно, что за значение.

## Константы: `const` и `constexpr`

```cpp
const int maxHealth = 100;         // нельзя изменить после инициализации
constexpr int maxEnemies = 64;     // известно ВО ВРЕМЯ КОМПИЛЯЦИИ
constexpr float gravity = 9.81f;
```

- **`const`** — «эту переменную нельзя менять». Значение может быть вычислено во время работы программы:
  ```cpp
  const int playerLevel = readLevelFromSave();   // вычисляется при запуске, потом не меняется
  ```
- **`constexpr`** — «это значение известно компилятору». Его можно использовать там, где нужна константа времени компиляции: размер массива, параметр шаблона, метка `case`.

Правило: если значение известно заранее, пиши `constexpr`. Если вычисляется при работе, но потом не меняется, пиши `const`. Всё, что не должно меняться, помечай одним из них: компилятор поймает случайное изменение, а читателю сразу видно, что это константа.

> [!compare] Константы в других языках
> | C++ | C# | Go |
> |---|---|---|
> | `constexpr int x = 5;` | `const int x = 5;` | `const x = 5` |
> | `const int x = f();` | `readonly int x = f();` (только поля) | (нет аналога для локальных) |

> [!deep] Под капотом: где живёт `constexpr`
> Для `constexpr int maxEnemies = 64;` компилятору обычно даже не нужна ячейка памяти: везде, где используется `maxEnemies`, он подставит число `64` прямо в машинную инструкцию. Ты видел это в [[00.2 Как исходник становится программой#Debug и Release|уроке 00.2]], где `square(7)` превратилось в `49`.

## Как число лежит в памяти

Число `int` — это 4 байта. В каком порядке они лежат? Проверим:

```cpp
#include <array>
#include <bit>
#include <cstdint>
#include <print>

int main() {
    int value = 0x12345678;
    // bit_cast берёт байты value и «переосмысливает» их как массив из 4 байт
    auto bytes = std::bit_cast<std::array<std::uint8_t, 4>>(value);
    std::println("{:02x} {:02x} {:02x} {:02x}", bytes[0], bytes[1], bytes[2], bytes[3]);
}
```

Вывод:
```
78 56 34 12
```

Байты лежат **в обратном порядке**: младший байт (`78`) по меньшему адресу. Такой порядок называется **little-endian** («с младшего конца»), и он используется всеми процессорами x86 и x64 и почти всеми ARM.

```
адрес:     +0    +1    +2    +3
байт:     0x78  0x56  0x34  0x12
           ↑ младший         ↑ старший
```

> [!engine] Когда порядок байт важен
> Пока данные живут внутри программы, порядок байт тебя не касается. Он становится важен, когда байты **покидают** программу или **приходят** извне: файлы форматов (в модуле 16 мы будем читать BMP-картинки байт за байтом), сетевые пакеты (в сетевых протоколах традиционно big-endian), сохранения игры, которые должны открываться на другой платформе.

> 3. Проверь, что `16777216.0f + 1.0f == 16777216.0f`. Затем попробуй то же с `double`.
> 4. Объяви `auto x = 7 / 2;` и наведи мышь на `x`: какой тип показывает IntelliSense? А какое значение?

> [!quiz]- Проверь себя
> 1. Сколько байт занимает `long` в MSVC под Windows? А в Linux x64?
> 2. Чему равно `010` в C++?
> 3. Что выведет `std::println("{}", 0.1f + 0.2f == 0.3f);` и почему нельзя на это полагаться ни в какую сторону?
> 4. Чем `int x{3.5};` отличается от `int x = 3.5;`?
> 5. Чем `const` отличается от `constexpr`?
> 6. Какого типа переменная `auto name = "Imp";`?
> 7. Что хранится в `int ammo;`, объявленной внутри функции без значения?
> 8. Почему для позиций в огромных открытых мирах `float` может оказаться мало?
>
> > [!success]- Ответы
> > 1. 4 байта в Windows, 8 байт в Linux x64. Если нужен точный размер, используй `std::int64_t`.
> > 2. 8: ведущий ноль означает восьмеричную запись.
> > 3. Результат зависит от того, как округлятся конкретные значения: может получиться и `true`, и `false`. Сравнивать дробные числа нужно с допуском (эпсилоном).
> > 4. `{}` запрещает сужающее преобразование: ошибка компиляции. `=` молча отбросит дробную часть (с предупреждением).
> > 5. `const` — нельзя изменять, но значение может вычисляться при работе программы. `constexpr` — значение известно при компиляции и может использоваться как константа времени компиляции.
> > 6. `const char*`, указатель на символы, а не `std::string`.
> > 7. Мусор: неопределённое значение. Чтение до присваивания — неопределённое поведение.
> > 8. У `float` ~7 значащих цифр. Чем дальше от начала координат, тем крупнее шаг между соседними значениями: на 100 км это уже миллиметры, на тысячах километров — метры. Объекты начинают дрожать.

> [!interview] Вопрос с собеседования
> **«Почему в играх используют `float`, а не `double`?»** Ожидают услышать: вдвое меньше памяти и нагрузки на кэш и шину памяти, вдвое больше элементов в SIMD-регистре, видеокарты оптимизированы под 32-битные вычисления, точности обычно достаточно. Плюс знание проблемы больших миров и её решений (floating origin, `double` для мировых координат, как в UE5).
