> - `std::getline` и ловушка с оставшимся переводом строки;

## Ввод: `std::cin`

```cpp
#include <iostream>   // std::cin живёт здесь
#include <print>

int main() {
    std::print("Сколько врагов на уровне? ");
    int enemies = 0;
    std::cin >> enemies;
    std::println("Готовим {} коек в лазарете", enemies);
}
```

- `std::cin` (*character input*) — стандартный поток ввода, объект из `<iostream>`.
- `>>` — оператор чтения: пропускает пробелы и переводы строк, читает «слово» и превращает его в значение нужного типа (здесь `int`).
- Чтения можно выстраивать в цепочку: `std::cin >> x >> y;` прочитает два числа, введённые через пробел или через Enter.

`std::cin >> word` для `std::string` читает **одно слово**, до первого пробела.

> [!warning] Помни про кириллицу
> Как мы выяснили в [[00.5 Проект курса в VS Code#Кириллица в консоли Windows|уроке 00.5]], русские буквы, **введённые** с клавиатуры, придут в программу не в UTF-8. Пока вводи латиницу и числа.

### Что если ввели не число

Это обязательно случится. Пользователь вводит `abc` там, где ждали число, и:

1. Чтение не удаётся, переменная получает значение `0`.
2. Поток `std::cin` переходит в **состояние ошибки** (fail state).
3. **Все последующие** чтения сразу завершаются неудачей, даже не пытаясь читать. А символы `abc` так и остаются непрочитанными во входном буфере.

Если чтение было в цикле, получается бесконечный цикл, который мгновенно засыпает экран сообщениями. Правильное чтение числа выглядит так:

```cpp
#include <iostream>
#include <limits>
#include <print>

int main() {
    std::print("Выбери уровень сложности (1-3): ");
    int difficulty = 0;

    while (!(std::cin >> difficulty) || difficulty < 1 || difficulty > 3) {
        if (std::cin.eof()) {        // ввод закрыт (Ctrl+Z, Enter) — читать больше нечего
            return 1;
        }
        std::cin.clear();            // 1. снять состояние ошибки
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');   // 2. выбросить остаток строки
        std::print("Нужно число от 1 до 3: ");
    }

    std::println("Сложность: {}", difficulty);
}
```

Разберём условие цикла:
- `std::cin >> difficulty` возвращает сам поток, а поток в условии превращается в `true`, если он **в порядке**. `!(...)` означает «чтение не удалось»;
- `|| difficulty < 1 || difficulty > 3` — если число прочиталось, но не подходит, тоже повторяем.

Внутри цикла:
- `std::cin.clear()` сбрасывает флаг ошибки, иначе поток не будет даже пытаться читать дальше;
- `std::cin.ignore(максимум, '\n')` выбрасывает всё до конца строки включительно, вместе с введённым мусором;
- проверка `eof()` защищает от бесконечного цикла, если ввод закончился совсем (в консоли Windows конец ввода — это `Ctrl+Z` и затем Enter).

> [!tip] Это кандидат в функцию
> Такой код нужен при каждом вводе числа, и копировать его из места в место — плохая идея. В модуле 02 мы оформим его функцией `readInt(min, max)` и будем пользоваться ей во всех консольных играх.

### Чтение целой строки: `std::getline`

`>>` читает до пробела. Чтобы прочитать строку целиком, используй `std::getline`:

```cpp
std::string playerName;
std::getline(std::cin, playerName);   // всё до Enter, включая пробелы
```

> [!warning] Ловушка: `>>` и потом `getline`
> ```cpp
> int age = 0;
> std::cin >> age;                  // пользователь ввёл "25" и нажал Enter
> std::string name;
> std::getline(std::cin, name);     // name — ПУСТАЯ строка!
> ```
> `>>` прочитал `25`, но **перевод строки** от Enter остался во входном буфере. `getline` сразу же нашёл этот `'\n'` и вернул пустую строку.
>
> Решение — пропустить пробельные символы перед `getline` манипулятором `std::ws`:
> ```cpp
> std::getline(std::cin >> std::ws, name);
> ```

## `std::string`

```cpp
#include <string>

std::string name = "Doomguy";
std::string empty;                 // пустая строка
std::string line(20, '=');         // "====================": 20 символов '='
```

### Основные операции

| Операция | Пример | Результат |
|---|---|---|
| Склейка | `"Doom" + std::string("guy")` | `"Doomguy"` |
| Дописать | `name += "!";` | `"Doomguy!"` |
| Длина в байтах | `name.size()` | `7` |
| Пустая? | `name.empty()` | `false` |
| Символ по индексу | `name[0]` | `'D'` |
| С проверкой индекса | `name.at(100)` | исключение `std::out_of_range` |
| Первый/последний | `name.front()`, `name.back()` | `'D'`, `'y'` |
| Подстрока | `name.substr(4, 3)` | `"guy"`: с позиции 4, длиной 3 |
| Поиск | `name.find("guy")` | `4`; или `std::string::npos`, если не найдено |
| Сравнение | `name == "Doomguy"`, `a < b` | лексикографически, по кодам символов |
| Вставка, удаление | `name.insert(0, "Mr. ")`, `name.erase(0, 4)` | |
| Число → строка | `std::to_string(42)` | `"42"` |
| Строка → число | `std::stoi("42")`, `std::stof("3.5")` | `42`, `3.5f` |

```cpp
std::string text = "Doomguy picks up the shotgun";
auto pos = text.find("shotgun");
if (pos != std::string::npos) {
    std::println("Нашли с позиции {}: {}", pos, text.substr(pos));   // 21: shotgun
}
```

> [!warning] Сравнение строк — по кодам символов
> `std::string("Zombie") < "apple"` — **истина**: код заглавной `Z` (90) меньше кода строчной `a` (97). Все заглавные латинские буквы «меньше» всех строчных. Для сортировки «как в словаре» нужно сначала привести строки к одному регистру.

> [!warning] `std::stoi` и плохой ввод
> `std::stoi("abc")` не возвращает 0, а **выбрасывает исключение** `std::invalid_argument`, и необработанное исключение завершает программу. Исключения мы разберём в модуле 09. Пока для чтения чисел пользуйся `std::cin >> число` с проверкой, как выше.

### Строки — это значения

Это важнейшее отличие от C#, Java, Python и Go:

```cpp
std::string a = "Imp";
std::string b = a;      // b — ПОЛНАЯ КОПИЯ a: свои байты в своей памяти
b[0] = 'W';             // меняем только b
std::println("{} {}", a, b);   // Imp Wmp
```

> [!compare] Строки в разных языках
> | | Изменяемая? | Присваивание `b = a` |
> |---|---|---|
> | **C#** `string` | нет | копирует ссылку на тот же объект |
> | **Python** `str` | нет | копирует ссылку |
> | **Go** `string` | нет | копирует «заголовок», байты общие |
> | **C++** `std::string` | **да** | **копирует все байты** |
>
> В C# и Python строки неизменяемы, поэтому делить один объект между переменными безопасно. В C++ строка изменяема, и каждая переменная владеет **своей** копией. Это безопасно (изменение одной не затронет другую), но копирование длинной строки стоит выделения памяти и копирования байт. Поэтому в модуле 02 мы научимся передавать строки в функции **по ссылке**, без копирования.

### Размер — в байтах, а не в буквах

```cpp
std::string greeting = "Привет";
std::println("{}", greeting.size());   // 12
```

`size()` возвращает количество **байт** (`char`), а не букв. Каждая кириллическая буква в UTF-8 занимает 2 байта. Поэтому `greeting[0]` — это не «П», а первая **половинка** буквы «П». Для работы с латиницей и цифрами (имена файлов, команды, идентификаторы) это не важно, а для обработки русского текста по буквам нужна отдельная работа с UTF-8. Мы займёмся этим, когда будем рисовать текст растровым шрифтом в модуле 16.

> [!deep] Под капотом: оптимизация коротких строк
> Внутри `std::string` — указатель на буфер с символами, длина и вместимость. Длинный текст лежит в **куче** (динамической памяти, модуль 03), и создание такой строки — это выделение памяти, операция относительно дорогая.
>
> Но большинство строк в программах короткие. Поэтому все реализации используют **SSO** (Small String Optimization): короткая строка хранится **прямо внутри объекта** `std::string`, без обращения к куче. В MSVC объект `std::string` занимает 32 байта (в Debug-сборке 40: там есть дополнительный указатель для отладочных проверок), и строки до **15 символов** помещаются внутрь. Можно проверить: `std::string{}.capacity()` возвращает 15.
>
> Следствие: строка из 15 символов создаётся и копируется очень быстро, а строка из 16 уже требует выделения памяти.

> [!engine] Строки в движках
> Сравнение строк — посимвольное, а создание — часто выделение памяти. В горячем коде движка (тысячи раз за кадр) строки — враг производительности. Поэтому движки заменяют строки-идентификаторы **хешами**: число, вычисленное по строке один раз. Unreal Engine хранит имена объектов в типе `FName`: внутри это индекс в глобальной таблице, и сравнение двух `FName` — одно сравнение чисел. Мы сделаем похожий тип `StringId` для Ember.

## `std::format`: форматирование в строку

`std::println` печатает. А `std::format` с тем же синтаксисом **возвращает строку**:

```cpp
#include <format>

std::string hud = std::format("HP: {:3}/{:3}  Патроны: {:2}", health, maxHealth, ammo);
std::string bar = std::format("[{:-<20}]", std::string(health / 5, '#'));   // [#########-----------]
```

Пригодится, когда строку нужно сохранить, передать дальше или измерить её длину перед выводом.

## Случайные числа

Случайность нужна играм постоянно: урон, шанс критического удара, разброс пуль, генерация уровней.

### Не используй `rand()`

В старом коде и туториалах встречается:

```cpp
int dice = rand() % 6 + 1;   // так делали в C
```

Проблемы:
- в MSVC `rand()` возвращает числа только до **32 767** (`RAND_MAX`): для числа от 0 до 100 000 не годится вовсе;
- качество генератора низкое: заметные закономерности в младших битах;
- `% 6` вносит **смещение**: при неравномерном делении одни значения выпадают чаще других;
- одно скрытое глобальное состояние на всю программу.

### `<random>`: генератор + распределение

Современный подход разделяет две вещи:
- **генератор** (engine) выдаёт поток «сырых» случайных битов;
- **распределение** (distribution) превращает их в числа нужного вида: целые в диапазоне, дробные, с заданной вероятностью.

```cpp
#include <print>
#include <random>

int main() {
    // Генератор: «вихрь Мерсенна», засеянный настоящей случайностью
    std::random_device seedSource;
    std::mt19937 rng(seedSource());

    // Распределения
    std::uniform_int_distribution<int> d6(1, 6);             // целые от 1 до 6 ВКЛЮЧИТЕЛЬНО
    std::uniform_real_distribution<float> spread(-2.0f, 2.0f); // дробные в [-2, 2)
    std::bernoulli_distribution critChance(0.15);            // true с вероятностью 15%

    std::println("Бросок кубика: {}", d6(rng));
    std::println("Разброс пули: {:.2f} градуса", spread(rng));
    std::println("Крит? {}", critChance(rng));
}
```

- `std::random_device` — источник **настоящей** случайности от операционной системы. Медленный, поэтому используется только для начального значения (**зерна**, seed).
- `std::mt19937` — быстрый генератор (алгоритм Mersenne Twister). Создаётся **один раз** и используется для всех случайных чисел программы.
- Распределение вызывается с генератором в скобках: `d6(rng)`.

> [!warning] Создавай генератор один раз
> Частая ошибка — создавать `std::mt19937` заново перед каждым броском. Это медленно (у `mt19937` большое внутреннее состояние: 5000 байт), а с одинаковым зерном вообще даёт одно и то же число каждый раз.

### Повторяемая случайность

Если засеять генератор **фиксированным** числом, последовательность «случайных» чисел будет каждый раз одинаковой:

```cpp
std::mt19937 rng(42);   // зерно 42: при каждом запуске одна и та же последовательность
```

Звучит как недостаток, но для игр это суперсила.

> [!engine] Зерно — это целый мир
> - **Процедурная генерация**: мир Minecraft или уровень в рогалике строится из зерна. Одно число полностью определяет мир, поэтому сохранять сам мир не обязательно, хватит зерна. Игроки делятся зёрнами интересных миров.
> - **Повторы и сетевая игра**: если все случайные числа идут из генератора с известным зерном, игру можно воспроизвести точно, записав только ввод игрока. На этом построены повторы в стратегиях и «детерминированная» сетевая игра (lockstep).
> - **Отладка**: баг, который проявляется «иногда», с фиксированным зерном становится воспроизводимым.
>
> Тонкость: стандарт точно описывает **алгоритм** `std::mt19937`, но **не** распределения. `std::uniform_int_distribution` в MSVC и в GCC может выдать разные числа из одного и того же зерна. Поэтому движки, которым нужна одинаковая генерация на всех платформах, пишут свои генераторы и распределения. Мы сделаем свой быстрый генератор в одном из следующих модулей.

## Управление консолью — цвета и очистка экрана

Терминалы понимают **управляющие последовательности ANSI**: специальные строки, которые начинаются с символа ESC (`\x1b`) и не печатаются, а управляют терминалом.

| Последовательность | Действие |
|---|---|
| `\x1b[2J\x1b[H` | Очистить экран и поставить курсор в левый верхний угол |
| `\x1b[31m` | Красный текст (32 зелёный, 33 жёлтый, 34 синий, 35 пурпурный, 36 голубой) |
| `\x1b[1m` | Жирный (яркий) текст |
| `\x1b[0m` | Сбросить цвет и стиль |
| `\x1b[?25l` / `\x1b[?25h` | Скрыть / показать курсор |

```cpp
std::println("\x1b[31mКРИТИЧЕСКИЙ УРОН!\x1b[0m Обычный текст");
```

Встроенный терминал VS Code и Windows Terminal понимают эти последовательности. С их помощью в практикуме мы сделаем анимацию в консоли.

> [!warning] Если вместо цвета видны символы `←[31m`
> Значит, консоль не включила обработку этих последовательностей (так бывает в старом окне `cmd.exe`). Включить её можно вызовом WinAPI в начале `main`. Пока считай это заклинанием, WinAPI мы разберём в модуле 15:
> ```cpp
> #include <windows.h>
>
> // в начале main:
> HANDLE console = GetStdHandle(STD_OUTPUT_HANDLE);
> DWORD mode = 0;
> GetConsoleMode(console, &mode);
> SetConsoleMode(console, mode | ENABLE_VIRTUAL_TERMINAL_PROCESSING);
> ```

> [!try] Попробуй сам
> 1. Спроси у игрока имя (одним словом) и возраст, затем поприветствуй его. Попробуй ввести вместо возраста буквы и посмотри, что получится без защиты от ошибок.
> 2. Сделай так, чтобы имя можно было ввести с пробелами (`getline`), причём **после** ввода возраста.
> 3. Брось два кубика d6 тысячу раз и посчитай, сколько раз выпала сумма 7. Должно получиться около 1/6 всех бросков. Почему именно 7 — самая частая сумма?
> 4. Засей генератор числом 2026 и напечатай 5 бросков d20. Запусти программу несколько раз. Что заметил?
> 5. Напечатай полоску здоровья `[#######---]` красным цветом, если здоровья меньше 30%, и зелёным иначе.

> [!quiz]- Проверь себя
> 1. Что происходит с `std::cin`, если ввести `abc` вместо числа? Какие две функции нужно вызвать, чтобы продолжить ввод?
> 2. Почему `getline` после `cin >> x` возвращает пустую строку?
> 3. После `std::string b = a; b += "!";` изменится ли `a`?
> 4. Чему равно `std::string("Ёж").size()`?
> 5. Чем плох `rand() % 6 + 1`?
> 6. Зачем разделены генератор и распределение?
> 7. Почему иногда генератор специально засевают константой?
>
> > [!success]- Ответы
> > 1. Чтение не удаётся, переменная получает 0, поток переходит в состояние ошибки, и все следующие чтения сразу проваливаются. Нужно `std::cin.clear()` (снять ошибку) и `std::cin.ignore(...)` (выбросить мусор из буфера).
> > 2. `>>` оставляет в буфере символ перевода строки от Enter, и `getline` читает «строку» до этого символа, то есть пустую. Лечится `std::getline(std::cin >> std::ws, s)`.
> > 3. Нет. `std::string` копируется целиком, у `b` своя копия.
> > 4. `4`: две кириллические буквы по 2 байта в UTF-8.
> > 5. Маленький диапазон (`RAND_MAX` = 32767 в MSVC), низкое качество, смещение из-за `%`, глобальное скрытое состояние.
> > 6. Генератор отвечает за качество и скорость случайных битов, распределение — за форму результата (диапазон, тип, вероятности). Их можно комбинировать независимо.
> > 7. Для воспроизводимости: процедурная генерация по зерну, повторы, детерминированная сетевая игра, воспроизведение багов.
