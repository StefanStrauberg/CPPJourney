# 01.5 Управление потоком

> [!abstract] О чём урок
> - `if`/`else`, `if` с инициализатором, тернарный оператор;
> - `switch`: проваливание (fallthrough) и почему в C# его запретили;
> - циклы `while`, `do-while`, `for`, `for` по диапазону;
> - `break`, `continue` и как выйти из вложенного цикла без меток;
> - скелет **игрового цикла**;
> - под капотом: условные переходы, таблицы переходов и предсказание ветвлений.
>
> Синтаксис здесь почти как в C#, Go и Java, поэтому урок сосредоточен на **отличиях** и на том, во что всё это превращается в машинном коде.

## `if` и `else`

```cpp
#include <print>

int main() {
    int health = 35;

    if (health <= 0) {
        std::println("Игрок погиб");
    } else if (health < 30) {
        std::println("Критическое состояние!");
    } else if (health < 70) {
        std::println("Ранен");
    } else {
        std::println("Полон сил");
    }
}
```

Скобки вокруг условия обязательны (в отличие от Go). Фигурные скобки для одной инструкции формально не нужны, но **ставь их всегда**:

```cpp
if (health <= 0)
    std::println("Игрок погиб");
    respawn();          // выполнится ВСЕГДА: отступ компилятору безразличен
```

Знаменитая уязвимость Apple «goto fail» (2014) — ровно такая ошибка: лишняя строка без фигурных скобок отключила проверку SSL-сертификатов на миллионах устройств.

### Условие — не обязательно `bool`

В C++ условием может быть число: ноль считается ложью, всё остальное — истиной.

```cpp
int ammo = 5;
if (ammo) { ... }        // то же, что if (ammo != 0)
```

> [!compare] C# и Go строже
> В C# и Go условие обязано быть `bool`: `if (ammo)` там не скомпилируется. В C++ это наследие языка C, где `bool` вообще появился только в 1999 году. Для чисел лучше писать сравнение явно (`ammo > 0`): так понятнее, что имелось в виду.

### `if` с инициализатором (C++17)

Переменную можно объявить прямо в `if`, и она будет видна **только** внутри `if`/`else`:

```cpp
if (int damage = baseDamage * multiplier; damage > 50) {
    std::println("Критический удар: {}", damage);
} else {
    std::println("Обычный удар: {}", damage);
}
// здесь damage уже не существует
```

Удобно, когда переменная нужна только для проверки: она не «засоряет» остальную функцию. Аналог в Go: `if v := f(); v > 0 { }`.

### Тернарный оператор

`условие ? значение_если_да : значение_если_нет` — выражение, а не инструкция, поэтому его можно подставить куда угодно:

```cpp
int damage = isCritical ? baseDamage * 2 : baseDamage;
std::println("Статус: {}", health > 0 ? "жив" : "мёртв");
```

Не вкладывай тернарные операторы друг в друга: `a ? b : c ? d : e` читается с трудом.

## `switch`

`switch` выбирает ветку по **целому** значению (или символу, или перечислению):

```cpp
#include <print>

int main() {
    int weaponSlot = 3;

    switch (weaponSlot) {
        case 1:
            std::println("Кулаки");
            break;
        case 2:
            std::println("Пистолет");
            break;
        case 3:
        case 4:                          // несколько меток — одна ветка
            std::println("Дробовик");
            break;
        default:                         // всё остальное
            std::println("Пустой слот");
            break;
    }
}
```

> [!warning] Не забывай `break`
> Без `break` выполнение **проваливается** (fallthrough) в следующую ветку:
> ```cpp
> switch (difficulty) {
>     case 3:
>         spawnBoss();          // нет break!
>     case 2:
>         spawnExtraEnemies();
>     case 1:
>         spawnEnemies();
>         break;
> }
> ```
> При `difficulty == 3` выполнятся все три вызова. Иногда это и нужно, как здесь: «на сложности 3 всё, что на 2, плюс босс». Но чаще пропущенный `break` — баг. Если проваливание задумано, пометь его атрибутом `[[fallthrough]];`. Читателю станет ясно, что это не ошибка, а компилятор не будет предупреждать.

> [!compare] `switch` в других языках
> - **C#** запрещает неявное проваливание: каждая непустая ветка обязана заканчиваться `break`, `return` или `goto case`.
> - **Go** по умолчанию **не** проваливается; проваливание нужно просить явно словом `fallthrough`.
> - **C#** и **Go** умеют `switch` по строкам. **C++ — нет**: только целые типы, символы и перечисления. Метки `case` должны быть **константами времени компиляции**.

Если внутри `case` нужно объявить переменную, оберни ветку в фигурные скобки, иначе компилятор пожалуется, что прыжок на следующую метку «перепрыгивает инициализацию»:

```cpp
case 2: {
    int bullets = 12;
    reload(bullets);
    break;
}
```

> [!deep] Под капотом: таблица переходов
> Цепочка `if`/`else if` проверяет условия по очереди: при 50 вариантах в худшем случае 50 сравнений. Для `switch` с плотными метками (1, 2, 3, …, 50) компилятор строит **таблицу переходов** (jump table): массив адресов кода, по одному на каждое значение. Выбор ветки становится одной операцией: «взять адрес из таблицы по индексу и прыгнуть». Поэтому, кстати, метки и должны быть константами: таблица строится во время компиляции. Для разреженных меток (1, 1000, 50000) компилятор использует двоичный поиск или цепочку сравнений.
>
> Интерпретаторы байт-кода (виртуальные машины скриптовых языков в движках) традиционно построены на огромном `switch` по коду операции.

## Циклы

### `while` и `do-while`

```cpp
int health = 40;
while (health < 100) {      // проверка ДО каждой итерации
    health += 15;
}
// 40 → 55 → 70 → 85 → 100: при 100 условие ложно, цикл закончился.
// А если начать с 45? (Ответ в «Попробуй сам» в конце урока.)
```

`do-while` проверяет условие **после** итерации, поэтому тело выполняется хотя бы один раз. Типичное применение — меню, которое нужно показать минимум однажды:

```cpp
int choice = 0;
do {
    std::println("1) Новая игра  2) Загрузить  3) Выход");
    std::cin >> choice;              // ввод разберём в следующем уроке
} while (choice < 1 || choice > 3);  // повторять, пока ввод неверный
```

### `for`

```cpp
for (инициализация; условие; шаг) {
    тело
}
```

```cpp
for (int i = 3; i > 0; --i) {
    std::println("{}...", i);
}
std::println("В бой!");
```

Переменная `i`, объявленная в `for`, видна только внутри цикла. Любую из трёх частей можно опустить: `for (;;)` — бесконечный цикл.

Вложенные циклы — способ обойти двумерное пространство: строки и столбцы карты, пиксели экрана.

```cpp
#include <print>

int main() {
    constexpr int width = 12;
    constexpr int height = 5;

    for (int y = 0; y < height; ++y) {
        for (int x = 0; x < width; ++x) {
            bool isWall = (x == 0 || x == width - 1 || y == 0 || y == height - 1);
            std::print("{}", isWall ? '#' : '.');
        }
        std::println("");    // конец строки
    }
}
```

Вывод:
```
############
#..........#
#..........#
#..........#
############
```

> [!engine] Порядок вложенных циклов важен
> Обрати внимание: внешний цикл по `y` (строки), внутренний по `x` (столбцы). Это не случайность. Изображения и карты в памяти хранятся **построчно**: сначала вся строка 0, потом вся строка 1. Перебор «по строкам, внутри по столбцам» идёт по памяти **последовательно**, и кэш процессора работает идеально. Если поменять циклы местами, программа будет прыгать по памяти с шагом в целую строку. Для картинки 4K это может замедлить обход **в разы**. Мы измерим это в модуле 11.

### `for` по диапазону

Чтобы перебрать все элементы коллекции, есть короткая форма:

```cpp
for (int damage : {10, 25, 40}) {
    std::println("Урон: {}", damage);
}
```

`for (элемент : коллекция)` — аналог `foreach` в C# и `for _, v := range` в Go. С настоящими коллекциями (`std::array`, `std::vector`) мы будем использовать его в [[01.7 Первые составные типы — array, vector, struct|уроке 01.7]].

## `break` и `continue`

- `break` — немедленно выйти из цикла (или `switch`);
- `continue` — пропустить остаток итерации и перейти к следующей.

```cpp
for (int wave = 1; wave <= 10; ++wave) {
    if (wave % 5 == 0) {
        std::println("Волна {}: босс!", wave);
        continue;                 // обычных врагов в этой волне нет
    }
    if (wave > 7) {
        std::println("Победа досрочно!");
        break;                    // дальше волны 8 не идём
    }
    std::println("Волна {}: {} врагов", wave, wave * 3);
}
```

### Выход из вложенных циклов

`break` выходит только из **самого внутреннего** цикла. В Go и Java есть метки (`break outer`), а в C++ — нет. Варианты:

1. **Флаг**:
   ```cpp
   bool found = false;
   for (int y = 0; y < height && !found; ++y) {
       for (int x = 0; x < width; ++x) {
           if (isTreasure(x, y)) {
               found = true;
               break;
           }
       }
   }
   ```
2. **Вынести циклы в функцию** и выйти через `return`. Обычно это лучший вариант: у такого кода появляется имя (`findTreasure`). Функции — в модуле 02.
3. **`goto`**. Да, в C++ он есть. В общем случае пользоваться им не стоит, но выход из глубоко вложенных циклов — единственный случай, где `goto` иногда считается допустимым.

## Игровой цикл

Почти любая игра — это бесконечный цикл:

```cpp
bool running = true;
while (running) {
    processInput();    // что нажал игрок
    update();          // сдвинуть мир на один шаг: физика, ИИ, анимации
    render();          // нарисовать кадр
}
```

Каждый проход — один **кадр**. 60 проходов в секунду — 60 FPS. Внутри `update` обычно тоже циклы: по всем врагам, по всем пулям, по всем частицам.

> [!engine] Цикл — сердце движка
> Этот цикл — главная структура любого движка. В модуле 07 мы напишем настоящий, с окном и измерением времени кадра, а в модуле 15 добавим **фиксированный шаг** физики (чтобы игра вела себя одинаково при 30 и при 240 FPS). А пока в практикуме этого модуля сделаем текстовый вариант: пошаговую «Арену» и «Жизнь» Конвея.

## Под капотом: ветвления в машинном коде

> [!deep] Как процессор выполняет `if`
> В машинном коде нет `if` и `while`. Есть **сравнение** и **условный переход**:
> ```asm
> cmp   eax, 30        ; сравнить health с 30
> jge   not_critical   ; если больше или равно — перепрыгнуть
> ...                  ; код «Критическое состояние!»
> not_critical:
> ```
> Цикл — это переход **назад** к началу тела, пока условие верно.
>
> Современный процессор выполняет инструкции **конвейером**: пока одна инструкция заканчивается, следующие десять уже начали выполняться. Но на условном переходе процессор ещё не знает, куда пойдёт выполнение. Поэтому он **угадывает** (branch prediction) и продолжает работать по предсказанной ветке. Если угадал — переход ничего не стоил. Если ошибся — всю начатую работу приходится выбрасывать, это стоит **15–20 тактов**.
>
> Предсказатель отлично угадывает закономерные ветвления: условие цикла (почти всегда «продолжить») или `if`, который почти всегда идёт в одну сторону. А на **случайных** ветвлениях («этот враг жив? а этот?» в перемешанном массиве) он ошибается в половине случаев.
>
> На знаменитом примере со StackOverflow суммирование элементов массива больше 128 работает **в несколько раз быстрее на отсортированном массиве**, чем на перемешанном, хотя работа та же самая. Причина: в отсортированном массиве `if (x >= 128)` сначала всегда ложно, потом всегда истинно, и предсказатель не ошибается. Мы повторим этот эксперимент в модуле 11, а в модуле 13 узнаем, как движки вообще избавляются от таких ветвлений, раскладывая данные по разным массивам.
