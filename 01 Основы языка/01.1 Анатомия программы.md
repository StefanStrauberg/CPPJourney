## Программа целиком

```cpp
// Однострочный комментарий: от // до конца строки
/* Многострочный комментарий:
   всё между этими скобками */

#include <print>    // подключаем std::print и std::println
#include <string>   // подключаем std::string

int main() {
    std::string name = "Doomguy";
    int health = 100;

    std::println("Игрок {} готов к бою, здоровье: {}", name, health);
    return 0;
}
```

Вывод:
```
Игрок Doomguy готов к бою, здоровье: 100
```

Разберём по частям.

### `#include`

Строки, начинающиеся с `#`, — директивы **препроцессора** (помнишь [[00.2 Как исходник становится программой#Этап 1. Препроцессор|урок 00.2]]?). `#include <print>` вставляет в программу текст заголовка `print`, в котором **объявлены** функции `std::print` и `std::println`. Без этого компилятор не знает, что такое `std::println`, и выдаст ошибку.

- `#include <имя>` (угловые скобки) — заголовок из стандартной библиотеки или системы. Компилятор ищет его в системных папках.
- `#include "имя.h"` (кавычки) — твой собственный заголовок. Сначала ищется рядом с текущим файлом, потом в системных папках.

Заголовки стандартной библиотеки C++ пишутся **без расширения**: `<print>`, `<string>`, `<vector>`. Заголовки, унаследованные от языка C, начинаются с буквы `c`: `<cmath>`, `<cstdint>`, `<cstdio>`.

> [!compare] Подключение кода в разных языках
> | C++ | C# | Go | Python |
> |---|---|---|---|
> | `#include <print>` | `using System;` | `import "fmt"` | `import sys` |
>
> Похоже, но механизм совсем другой: в C++ это **текстовая вставка** файла, а не ссылка на модуль.

### Функция `main`

```cpp
int main() {
    ...
}
```

`main` — **точка входа**: код запуска программы вызывает её первой. В программе должна быть ровно одна функция `main`.

- `int` перед именем — тип **возвращаемого значения**. `main` возвращает **код возврата** процесса ([[00.2 Как исходник становится программой#Этап 4. Запуск|урок 00.2]]).
- `()` — список параметров, здесь пустой. Есть вторая форма, `int main(int argc, char* argv[])`, для аргументов командной строки; её мы разберём, когда научимся работать с указателями.
- `{ ... }` — **тело** функции.

`return 0;` в конце `main` можно не писать: только для `main` компилятор подставляет его сам.

> [!compare] Точка входа
> - C#: `static void Main(string[] args)` внутри класса (или top-level statements без всякого `Main`);
> - Go: `func main()` в пакете `main`;
> - Python: точки входа нет, файл выполняется сверху вниз;
> - C++: свободная функция `int main()`, не внутри класса. В C++ функции не обязаны принадлежать классу.

### Инструкции и блоки

- Каждая **инструкция** (statement) заканчивается точкой с запятой `;`.
- Фигурные скобки `{ }` объединяют инструкции в **блок**.
- Переводы строк и отступы компилятору безразличны. Это можно записать в одну строку, и программа будет работать (но читать её будет мучительно):

```cpp
#include <print>
int main(){int health=100;std::println("{}",health);}
```

> [!compare] Python
> В Python отступы — часть синтаксиса. В C++ отступы нужны только людям: компилятор смотрит на `{}` и `;`.

### Пространство имён std

`std::println`, `std::string` — все имена стандартной библиотеки живут в **пространстве имён** `std` (от *standard*). Оператор `::` означает «имя внутри»: `std::println` — это «`println` из `std`».

Пространства имён нужны, чтобы имена из разных библиотек не конфликтовали. В модуле 02 мы создадим своё пространство имён `ember` для движка.

> [!warning] Почему не стоит писать `using namespace std;`
> Во многих учебниках в начале программы пишут:
> ```cpp
> using namespace std;   // теперь можно писать просто println, string...
> ```
> Эта строка вываливает **все** имена из `std` (а их тысячи: `count`, `distance`, `size`, `data`, `move`, `swap`…) в твою программу. Стоит назвать свою переменную или функцию `distance`, и начнутся конфликты с непонятными ошибками компиляции. В заголовочных файлах это вообще смертный грех: проблема расползается по всем файлам, которые их подключают.
>
> Профессиональный стиль: всегда писать `std::`. Пять лишних символов окупаются ясностью: сразу видно, что имя из стандартной библиотеки.

## Вывод: `std::print` и `std::println`

```cpp
std::print("без перевода строки");
std::println("с переводом строки в конце");
```

Первый аргумент — **строка формата**. Каждая пара `{}` в ней заменяется следующим аргументом:

```cpp
std::println("{} убил {} врагов за {} секунд", "Doomguy", 42, 93.5);
// Doomguy убил 42 врагов за 93.5 секунд
```

### Спецификаторы формата

Внутри `{}` после двоеточия можно указать, **как** выводить значение:

| Формат | Пример | Результат | Что делает |
|---|---|---|---|
| `{}` | `println("{}", 3.14159)` | `3.14159` | По умолчанию |
| `{:.2f}` | `println("{:.2f}", 3.14159)` | `3.14` | 2 знака после запятой |
| `{:5}` | `println("[{:5}]", 42)` | `[   42]` | Ширина 5 (числа прижаты вправо) |
| `{:<5}` | `println("[{:<5}]", 42)` | `[42   ]` | Прижать влево |
| `{:^7}` | `println("[{:^7}]", "HP")` | `[  HP   ]` | По центру |
| `{:*^9}` | `println("{:*^9}", "MENU")` | `**MENU***` | Заполнить звёздочками |
| `{:05}` | `println("{:05}", 42)` | `00042` | Дополнить нулями |
| `{:+}` | `println("{:+}", 5)` | `+5` | Всегда показывать знак |
| `{:x}` | `println("{:x}", 255)` | `ff` | Шестнадцатеричная система |
| `{:#x}` | `println("{:#x}", 255)` | `0xff` | С префиксом `0x` |
| `{:b}` | `println("{:b}", 5)` | `101` | Двоичная система |
| `{0}`, `{1}` | `println("{1} {0}", "мир", "Привет")` | `Привет мир` | Явный номер аргумента |
| `{{` `}}` | `println("{{}}")` | `{}` | Сами фигурные скобки |

Полный синтаксис: `{номер:заполнитель выравнивание знак # 0 ширина .точность тип}`. Ты будешь пользоваться им постоянно, особенно для таблиц и отладочного вывода.

> [!compare] Узнаёшь?
> - C#: `string.Format("{0} убил {1:F2}", name, x)` и `$"{name} убил {x:F2}"`;
> - Python: `"{} убил {:.2f}".format(name, x)` и f-строки `f"{name} убил {x:.2f}"`;
> - Go: `fmt.Printf("%s убил %.2f\n", name, x)`.
>
> Синтаксис `std::format` почти полностью взят из Python: `{:.2f}`, `{:>5}`, `{:x}` работают одинаково.

> [!deep] Под капотом: строка формата проверяется при компиляции
> В C# неправильная строка формата приводит к `FormatException` **во время работы**. В Python тоже. А в C++ вот такая программа просто **не скомпилируется**:
> ```cpp
> #include <print>
>
> int main() {
>     int health = 100;
>     std::println("Здоровье: {}, броня: {}", health);   // ошибка компиляции: аргументов меньше, чем {}
> }
> ```
> Строка формата должна быть известна во время компиляции. Компилятор разбирает её и проверяет, что число и типы аргументов подходят. Механизм называется `consteval`, мы разберём его в модуле 10. Сообщение об ошибке получается длинным и страшным:
> ```
> error C7595: "std::basic_format_string<char,int &>::basic_format_string": вызов немедленно
> вызываемой функции не является константным выражением
> note: см. использование "std::_You_see_this_error_because_arg_id_is_out_of_range"
> ```
> Разработчики стандартной библиотеки MSVC позаботились о тебе: имя функции в примечании само объясняет ошибку («ты видишь эту ошибку, потому что номер аргумента вне диапазона»). Когда видишь `C7595` рядом с `println` или `format`, проверь, совпадает ли число `{}` с числом аргументов.
>
> Отсюда следствие: строку формата нельзя собрать «на лету» из переменной. `std::println(myString)` не скомпилируется; нужно писать `std::println("{}", myString)`.

### Специальные символы в строках

Внутри строки в кавычках обратная косая черта `\` начинает **escape-последовательность**:

| Последовательность | Значение |
|---|---|
| `\n` | Перевод строки |
| `\t` | Табуляция |
| `\\` | Сама обратная косая черта |
| `\"` | Кавычка внутри строки |
| `\'` | Апостроф (нужен внутри символьного литерала `'\''`) |
| `\0` | Нулевой символ |
| `\x1b` | Символ с кодом 0x1B (ESC); пригодится для управления консолью |

```cpp
std::println("Путь: C:\\Games\\Doom\nВторая строка\t(после табуляции)");
```

Для текста с множеством `\` и кавычек есть **сырые строки**: всё между `R"(` и `)"` берётся буквально:

```cpp
std::println(R"(Путь: C:\Games\Doom, сказал "привет")");
```

## `std::cout`: классический вывод

`std::print` появился только в C++23. Двадцать пять лет до этого в C++ выводили так:

```cpp
#include <iostream>

int main() {
    int health = 100;
    std::cout << "Health: " << health << '\n';
}
```

- `std::cout` (*character output*) — объект «стандартный поток вывода».
- `<<` — оператор вывода в поток. Каждый `<<` отправляет в поток следующую часть, и их можно выстраивать в цепочку.
- `'\n'` — символ перевода строки (одинарные кавычки означают один символ, а не строку).

Ты встретишь `std::cout` почти в любом C++ коде, книге и ответе на StackOverflow, поэтому читать его нужно уметь. Но в курсе мы пишем на `std::println`: он короче, понятнее, проверяет формат при компиляции и правильно печатает кириллицу ([[00.5 Проект курса в VS Code#Кириллица в консоли Windows|урок 00.5]]).

> [!warning] `std::endl` против `'\n'`
> В старом коде часто встречается `std::cout << x << std::endl;`. `std::endl` не просто переводит строку: он ещё **сбрасывает буфер** (flush), то есть заставляет немедленно отправить накопленный текст в консоль. Это медленная операция. В цикле на 100 000 строк `std::endl` может замедлить вывод в разы. Используй `'\n'`, если тебе не нужен немедленный сброс.

> [!deep] Под капотом: буферизация вывода
> Отправка текста в консоль — системный вызов, переход из программы в ядро ОС, а это дорого (микросекунды). Поэтому потоки вывода копят текст в **буфере** в памяти и отправляют его крупными порциями: когда буфер заполнен, при `flush`, при завершении программы. Ради той же экономии движки пишут логи в файл не построчно, а пачками, и часто в отдельном потоке.

## Имена (идентификаторы)

Имена переменных, функций и типов:
- состоят из латинских букв, цифр и `_`;
- не начинаются с цифры;
- **чувствительны к регистру**: `health`, `Health` и `HEALTH` — три разных имени;
- не совпадают с **ключевыми словами** (`int`, `return`, `if`, `class`, `for`, `while`, `auto`, `const`, …).

> [!warning] Зарезервированные имена
> Имена, которые начинаются с **подчёркивания и заглавной буквы** (`_Health`) или содержат **двойное подчёркивание** (`my__var`), зарезервированы для компилятора и стандартной библиотеки. Использовать их — формально неопределённое поведение. Ты увидишь такие имена, если заглянешь внутрь STL (`_Myfirst`, `_Mypair`): так библиотека гарантирует, что её имена не пересекутся с твоими.

## Комментарии

```cpp
// Однострочный: для коротких пояснений

/* Многострочный:
   удобен, чтобы временно «выключить» кусок кода */

/// Документирующий комментарий. Многие инструменты (Doxygen, IntelliSense)
/// показывают его при наведении на функцию.
int computeDamage(int level);
```

Хороший комментарий объясняет **почему**, а не **что**: что делает код, видно из самого кода.

```cpp
health -= 10;  // плохо: «уменьшаем здоровье на 10»
health -= 10;  // хорошо: «урон от лавы фиксированный, броня не учитывается»
```

> 1. Напечатай таблицу из трёх строк: имя оружия по левому краю (ширина 12), урон по правому (ширина 5) и скорострельность с одним знаком после запятой:
>    ```
>    Pistol         10   2.5
>    Shotgun        70   1.0
>    Plasma         25  10.0
>    ```
> 2. Убери из `#include` строку `<print>` и посмотри, какую ошибку выдаст компилятор.
> 3. Напечатай число 48879 в шестнадцатеричной системе с префиксом. Что получилось?

> [!quiz]- Проверь себя
> 1. Чем отличается `#include <x>` от `#include "x"`?
> 2. Что вернёт программа операционной системе, если в `main` нет `return`?
> 3. Почему в профессиональном коде не пишут `using namespace std;`?
> 4. Что напечатает `std::println("[{:>6.1f}]", 3.14159);`?
> 5. Почему `std::println(text)`, где `text` — переменная-строка, не компилируется?
> 6. Чем `std::endl` отличается от `'\n'`?
>
> > [!success]- Ответы
> > 1. Угловые скобки: поиск только в системных папках (стандартная библиотека). Кавычки: сначала рядом с текущим файлом, потом в системных.
> > 2. `0`: для `main` компилятор неявно добавляет `return 0;`.
> > 3. Директива вываливает тысячи имён из `std` в текущую область, что ведёт к конфликтам имён. В заголовках проблема распространяется на все файлы, которые их подключают.
> > 4. `[   3.1]`: ширина 6, один знак после запятой, выравнивание вправо.
> > 5. Строка формата должна быть известна при компиляции, потому что проверяется компилятором. Правильно: `std::println("{}", text)`.
> > 6. `std::endl` ещё и сбрасывает буфер потока (flush), а это медленно. `'\n'` просто переводит строку.
