# 01.3 Операторы, выражения и преобразования

> [!abstract] О чём урок
> - арифметика: целочисленное деление и остаток (и чем они отличаются от Python);
> - переполнение: где оно определено, а где UB;
> - сравнения и логические операторы, короткое замыкание;
> - **неявные преобразования**: самый коварный источник багов в этом уроке (`-1 < 1u` — ложь!);
> - явные преобразования через `static_cast`, округление, математические функции;
> - приоритет операторов и порядок вычисления.

## Арифметические операторы

| Оператор | Действие | Пример | Результат |
|---|---|---|---|
| `+` `-` `*` | Сложение, вычитание, умножение | `7 * 3` | `21` |
| `/` | Деление | `7 / 2` | `3` (!) |
| `%` | Остаток от деления (только целые) | `7 % 3` | `1` |
| `-x` | Смена знака | `-health` | |

### Целочисленное деление

Если оба операнда **целые**, деление тоже **целочисленное**: дробная часть отбрасывается.

```cpp
int kills = 7;
int deaths = 2;
double ratio = kills / deaths;   // 3.0, а не 3.5!
```

Сначала вычисляется `kills / deaths` в целых числах (= 3), и только потом результат превращается в `double`. Чтобы получить 3,5, хотя бы один операнд должен быть дробным:

```cpp
double ratio = static_cast<double>(kills) / deaths;   // 3.5
double half = kills / 2.0;                            // 3.5: 2.0 — литерал double
```

> [!warning] Самый частый баг новичка
> «Среднее значение всегда получается целым», «процент всегда 0»: `int percent = score / maxScore * 100;` при `score < maxScore` даёт 0, потому что `score / maxScore` = 0. Переставь операции: `score * 100 / maxScore`, или считай в дробных.

### Деление отрицательных чисел

В C++ целочисленное деление **округляет к нулю**, а знак остатка совпадает со знаком **делимого**:

| Выражение | C++ | Python |
|---|---|---|
| `-7 / 2` | `-3` | `-7 // 2` = `-4` |
| `-7 % 2` | `-1` | `-7 % 2` = `1` |
| `7 % -2` | `1` | `7 % -2` = `-1` |

> [!compare] Python, C#, Go
> **C#** и **Go** ведут себя как C++ (округление к нулю). **Python** округляет вниз (к минус бесконечности), поэтому его остаток всегда неотрицателен при положительном делителе. Если переносишь формулу из Python, проверь, нет ли там отрицательных чисел.

> [!engine] Заворачивание индекса
> В играх часто нужно «зациклить» индекс: следующее оружие после последнего — первое, кадр анимации после последнего — нулевой. Для положительных чисел хватает `(i + 1) % count`. Но при движении назад `(i - 1) % count` при `i = 0` даёт **−1**, а не `count - 1`. Надёжная формула для любых `i`:
> ```cpp
> int wrapped = ((i % count) + count) % count;
> ```

> [!ub] Деление на ноль
> Целочисленное деление и остаток на ноль — **неопределённое поведение**. На x86 программа обычно падает с исключением *Integer division by zero*. У дробных чисел деление на ноль даёт `inf` или `nan` ([[01.2 Переменные и фундаментальные типы#Бесконечность и NaN|урок 01.2]]).

### Присваивание, составное присваивание, инкремент

```cpp
int ammo = 50;
ammo = ammo - 1;   // обычное присваивание
ammo -= 1;         // то же самое, короче. Есть +=, -=, *=, /=, %= и другие
ammo--;            // уменьшить на 1
--ammo;            // тоже уменьшить на 1
```

Разница между **префиксной** (`++x`) и **постфиксной** (`x++`) формой видна, только если использовать значение выражения:

```cpp
int a = 5;
int x1 = a++;   // x1 = 5: сначала взяли старое значение, потом увеличили (a = 6)
int x2 = ++a;   // x2 = 7: сначала увеличили (a = 7), потом взяли значение
```

> [!tip] Пиши `++i`
> Если значение выражения не нужно (например, в цикле `for`), пиши префиксную форму `++i`. Для `int` разницы нет, компилятор сгенерирует одинаковый код. Но для сложных типов (итераторы, модуль 06) постфиксная форма обязана сохранить копию старого значения, и это бывает дороже. Привычка `++i` ничего не стоит.

## Переполнение

У каждого целого типа ограниченный диапазон. Что будет, если выйти за его пределы?

**Беззнаковые типы** ведут себя предсказуемо: арифметика идёт **по модулю 2ᴺ**, значение «заворачивается»:

```cpp
unsigned int u = 0;
u = u - 1;          // 4294967295 (= 2³² − 1): определённое поведение
```

**Знаковые типы** при переполнении дают **неопределённое поведение**:

```cpp
int big = 2'147'483'647;   // максимум int
big = big + 1;             // UB! На практике часто -2147483648, но гарантий нет
```

> [!ub] Переполнение `int`
> Знаковое переполнение — UB, и компилятор пользуется этим для оптимизаций (вспомни пример с `x + 1 < x` из [[00.1 Что такое C++ и почему движки пишут на нём#Неопределённое поведение|урока 00.1]]). Если значение может стать большим (счёт очков, время в миллисекундах с начала игры, суммарный урон), выбирай тип с запасом: `std::int64_t`.
>
> Пример из жизни: если хранить время в миллисекундах в `int`, переполнение наступит через 2³¹ мс ≈ **24,8 дня** непрерывной работы. Серверы игр работают дольше.

## Сравнения и логика

| Оператор | Значение |
|---|---|
| `==` `!=` | Равно, не равно |
| `<` `>` `<=` `>=` | Меньше, больше, меньше или равно, больше или равно |
| `&&` | Логическое И |
| `\|\|` | Логическое ИЛИ |
| `!` | Логическое НЕ |

Результат сравнения имеет тип `bool`.

> [!warning] `=` и `==`
> `if (health = 0)` — это **присваивание**: `health` становится 0, условие ложно, и тело `if` никогда не выполнится. В C# и Go такой код не скомпилируется, а в C++ он корректен, хотя компилятор с `/W4` предупредит (`C4706`). Ещё одна причина читать предупреждения.

### Короткое замыкание

`&&` и `||` вычисляют правый операнд, **только если он нужен**:
- в `a && b`, если `a` ложно, `b` не вычисляется (результат уже ложь);
- в `a || b`, если `a` истинно, `b` не вычисляется.

На этом построены защитные проверки:

```cpp
// Если count == 0, деление не произойдёт: правая часть не вычислится
if (count != 0 && total / count > 10) {
    ...
}
```

Порядок проверок здесь важен: если их поменять местами, при `count == 0` случится деление на ноль.

## Неявные преобразования

Когда в выражении встречаются значения разных типов, C++ **молча** приводит их к общему типу. Правила сложные, но главные надо знать наизусть.

### 1. Целочисленное продвижение

Перед любой арифметикой типы **меньше `int`** (`char`, `short`, `bool`, `std::uint8_t`) превращаются в `int`:

```cpp
std::uint8_t b = 255;
auto sum = b + 1;      // sum имеет тип int, значение 256 (а не 0!)
std::uint8_t b2 = static_cast<std::uint8_t>(b + 1);   // а вот так 0: 256 не помещается в uint8_t
```

Процессору удобно считать в регистрах полного размера, поэтому язык и «расширяет» маленькие типы.

### 2. Обычные арифметические преобразования

Если операнды разных типов, «меньший» тип приводится к «большему»:
- целое + дробное → дробное: `5 + 2.5` → `7.5` (`double`);
- `float` + `double` → `double`;
- `int` + `long long` → `long long`;
- **знаковое + беззнаковое того же размера → беззнаковое**. Вот здесь и прячется ловушка.

### Ловушка — знаковое против беззнакового

```cpp
#include <print>

int main() {
    int i = -1;
    unsigned int one = 1;
    std::println("{}", i < one);   // false (!)
}
```

При сравнении `int` с `unsigned int` число `-1` превращается в `unsigned int`, то есть в 4 294 967 295. А оно, конечно, больше единицы. Компилятор с `/W4` предупреждает:

```
warning C4018: '<': несоответствие знака и беззнака
```

Где ты встретишь эту ловушку чаще всего: размеры контейнеров (`.size()`) имеют **беззнаковый** тип `std::size_t`. Выражение `v.size() - 1` для пустого вектора даёт не −1, а 18 446 744 073 709 551 615.

Для безопасного сравнения чисел разных знаков в C++20 есть функции из `<utility>`:

```cpp
std::cmp_less(i, one)      // true: сравнивает математически правильно
std::cmp_equal(a, b)       // также cmp_greater, cmp_less_equal и т.д.
```

> [!compare] Как решают другие языки
> **Go** запрещает смешивать типы в выражениях: нужно явное преобразование. **C#** расширяет `int` и `uint` до `long` при сравнении, и результат правильный. **C++** молча делает «как в C в 1972 году». Включённые предупреждения — твоя главная защита.

## Явные преобразования: `static_cast`

Чтобы преобразовать тип **явно**, используй `static_cast<НовыйТип>(значение)`:

```cpp
double precise = 3.99;
int whole = static_cast<int>(precise);          // 3: дробная часть отбрасывается (к нулю)
int negative = static_cast<int>(-3.99);         // -3
float f = static_cast<float>(someDouble);       // double → float
```

Длинно и некрасиво? Это специально. Явные преобразования **должны бросаться в глаза** при чтении кода: каждое из них — место, где программист сознательно рискует потерять данные.

> [!warning] Не используй приведение в стиле C
> В старом коде встречается `(int)x` или `int(x)`. Это «приведение в стиле C»: оно пробует подряд несколько видов преобразований, включая опасные, и молча делает самое мощное из них. `static_cast` разрешает только «разумные» преобразования, а остальные (их мы увидим в модуле 03) имеют свои отдельные, ещё более заметные имена.

### Округление

`static_cast<int>` всегда **отбрасывает** дробную часть. Если нужно округление, используй функции из `<cmath>`:

| Функция | `2.5` | `-2.5` | `2.1` | Что делает |
|---|---|---|---|---|
| `std::round` | `3` | `-3` | `2` | К ближайшему (половину от нуля) |
| `std::floor` | `2` | `-3` | `2` | Вниз |
| `std::ceil` | `3` | `-2` | `3` | Вверх |
| `std::trunc` | `2` | `-2` | `2` | К нулю (как `static_cast<int>`) |
| `std::lround` | `3` | `-3` | `2` | Как `round`, но сразу возвращает `long` |

> [!engine] floor против приведения к int
> Перевод мировой координаты в номер клетки сетки: `int cell = static_cast<int>(x / cellSize);`. Для положительных `x` работает, а для отрицательных сломается: `x = -0.5` попадёт в клетку 0 вместо −1, и клетка 0 станет «вдвое шире». Правильно: `static_cast<int>(std::floor(x / cellSize))`. Этот баг встречается в реальных движках, на картах, где есть отрицательные координаты.

## Математические функции

Заголовок `<cmath>`:

| Функция | Что делает |
|---|---|
| `std::abs(x)` | Модуль |
| `std::sqrt(x)` | Квадратный корень |
| `std::pow(x, y)` | xʸ (медленно! для квадрата пиши `x * x`) |
| `std::sin`, `std::cos`, `std::tan` | Тригонометрия, аргумент в **радианах** |
| `std::atan2(y, x)` | Угол вектора (x, y); главная функция для поворота «лицом к цели» |
| `std::hypot(x, y)` | √(x² + y²): длина вектора |
| `std::fmod(x, y)` | Остаток от деления дробных чисел |

В `<numbers>` (C++20) есть точные константы: `std::numbers::pi`, `std::numbers::pi_v<float>`, `std::numbers::sqrt2`. В `<algorithm>`: `std::min(a, b)`, `std::max(a, b)`, `std::clamp(x, lo, hi)` (ограничить значение диапазоном, в играх нужна постоянно).

```cpp
#include <algorithm>
#include <cmath>
#include <numbers>
#include <print>

int main() {
    float angleDegrees = 30.0f;
    float angleRadians = angleDegrees * std::numbers::pi_v<float> / 180.0f;

    float dirX = std::cos(angleRadians);
    float dirY = std::sin(angleRadians);
    std::println("Направление: ({:.3f}, {:.3f})", dirX, dirY);

    int health = 130;
    health = std::clamp(health, 0, 100);   // не меньше 0 и не больше 100
    std::println("Здоровье: {}", health);
}
```

Вывод:
```
Направление: (0.866, 0.500)
Здоровье: 100
```

> [!deep] Под капотом: деление — дорогая операция
> Сложение и умножение целых на современном x64 занимают 1–3 такта, а целочисленное деление — **десятки** тактов. Поэтому компилятор старается от деления избавиться:
> - деление беззнакового числа на степень двойки превращается в сдвиг: `x / 8` → `x >> 3` (подробно в [[01.4 Биты и байты]]);
> - деление на любую **константу** заменяется умножением на «магическое число» и сдвигом. В ассемблере Release-сборки на месте `x / 10` ты не увидишь инструкции деления.
>
> Дробное деление тоже медленнее умножения, но тут компилятор **не имеет права** заменить `x / 3.0f` на `x * (1.0f / 3.0f)`: результат может отличаться в последнем бите. Поэтому в горячем коде движков пишут вручную: `float inv = 1.0f / length;` и потом умножают на `inv` три координаты вместо трёх делений.

## Приоритет и порядок вычисления

Приоритет операторов в C++ почти как в математике: `*` и `/` раньше `+` и `-`, сравнения после арифметики, `&&` раньше `||`, присваивание в самом конце. Полная таблица содержит 17 уровней, и помнить её целиком не нужно.

> [!tip] Правило скобок
> Если не уверен в приоритете, **ставь скобки**. Особенно в выражениях с битовыми операторами: `flags & mask == 0` означает `flags & (mask == 0)`, а не то, что ты подумал (компилятор предупредит: `C4554`). Подробнее в следующем уроке.

**Порядок вычисления** — отдельная тема. В выражении `f() + g()` стандарт **не говорит**, какая функция вызовется первой. Если обе печатают что-то или меняют общие данные, результат зависит от компилятора.

> [!ub] Не изменяй переменную дважды в одном выражении
> ```cpp
> int i = 1;
> int x = i++ + i++;      // UB
> array[i] = i++;          // до C++17 — UB
> ```
> Правило простое: если переменная меняется в выражении, больше нигде в этом выражении её не используй. Такой код и читать невозможно.

> [!try] Попробуй сам
> 1. Вычисли среднее значение урона из трёх попаданий `int a = 17, b = 23, c = 31;` так, чтобы получилось дробное число с двумя знаками после запятой.
> 2. Проверь, что выдаёт `std::println("{}", -7 / 2 * 2 + -7 % 2);`. Почему получилось ровно −7? (Подсказка: это тождество выполняется всегда.)
> 3. Напиши выражение, которое переводит угол из радиан обратно в градусы, и проверь его на `std::numbers::pi / 4`.
> 4. Объяви `unsigned int lives = 0;` и выполни `lives--`. Что получилось? А если `int`?

> [!quiz]- Проверь себя
> 1. Чему равно `7 / 2 * 2` в C++?
> 2. Чему равно `-9 % 4` в C++? А в Python?
> 3. Что выведет `std::println("{}", -1 < 1u);`? Почему?
> 4. Какое из двух переполнений — UB: `unsigned` или `int`?
> 5. Почему `if (p != 0 && x / p > 3)` безопасно, а `if (x / p > 3 && p != 0)` — нет?
> 6. Чем `static_cast<int>(-2.7)` отличается от `std::floor(-2.7)`?
> 7. Какой тип у выражения `std::uint8_t(200) + std::uint8_t(100)` и чему оно равно?
>
> > [!success]- Ответы
> > 1. `6`: `7 / 2` = 3 (целочисленное деление), `3 * 2` = 6.
> > 2. В C++ `-1` (знак остатка как у делимого), в Python `3`.
> > 3. `false`: `-1` преобразуется в `unsigned int` и становится 4 294 967 295.
> > 4. Переполнение `int` (знакового) — UB. Беззнаковые типы заворачиваются по модулю 2ᴺ.
> > 5. Из-за короткого замыкания: в первом варианте при `p == 0` деление не выполнится. Во втором деление выполнится раньше проверки.
> > 6. `static_cast` отбрасывает дробную часть (к нулю): `-2`. `floor` округляет вниз: `-3.0`.
> > 7. `int` (целочисленное продвижение), значение `300`.

> [!interview] Вопрос с собеседования
> **«Что выведет код `unsigned a = 1; int b = -2; std::cout << (a + b > 0);` и почему?»** Ответ: `1` (true). `b` преобразуется в `unsigned`, сумма равна 2³² − 1. Хороший ответ также упоминает, как защититься: предупреждения компилятора, `std::cmp_*`, аккуратность с `.size()`.
