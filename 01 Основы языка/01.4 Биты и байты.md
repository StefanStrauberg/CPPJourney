# 01.4 Биты и байты

> [!abstract] О чём урок
> - двоичная и шестнадцатеричная системы: читаем числа так, как их видит процессор;
> - побитовые операторы `&`, `|`, `^`, `~`, `<<`, `>>`;
> - **битовые флаги**: десяток `bool` в одном числе;
> - упаковка цвета RGBA в 32 бита (так хранятся пиксели нашего будущего рендерера);
> - трюки со степенями двойки, которые встретятся в аллокаторах;
> - дополнительный код: как хранятся отрицательные числа;
> - заголовок `<bit>`.
>
> В прикладном программировании биты встречаются редко. В движках постоянно: цвета, флаги, маски коллизий, сжатие данных, хеши, аллокаторы. Урок длинный, но он окупится.

## Двоичная и шестнадцатеричная системы

Компьютер хранит всё в **битах**: 0 или 1. Восемь бит — **байт**. Число `int` — 32 бита.

В двоичной системе каждый разряд — степень двойки:

```
  разряд:   7    6    5    4    3    2    1    0
  вес:    128   64   32   16    8    4    2    1
  13 =      0    0    0    0    1    1    0    1   = 8 + 4 + 1
```

Двоичные числа длинные, поэтому программисты пишут их в **шестнадцатеричной** системе (hex): одна hex-цифра — ровно 4 бита.

| Двоичная | Hex | Десятичная | | Двоичная | Hex | Десятичная |
|---|---|---|---|---|---|---|
| `0000` | `0` | 0 | | `1000` | `8` | 8 |
| `0001` | `1` | 1 | | `1001` | `9` | 9 |
| `0010` | `2` | 2 | | `1010` | `A` | 10 |
| `0011` | `3` | 3 | | `1011` | `B` | 11 |
| `0100` | `4` | 4 | | `1100` | `C` | 12 |
| `0101` | `5` | 5 | | `1101` | `D` | 13 |
| `0110` | `6` | 6 | | `1110` | `E` | 14 |
| `0111` | `7` | 7 | | `1111` | `F` | 15 |

Байт — это ровно две hex-цифры: `0xFF` = `1111 1111` = 255. Число `0x12345678` — четыре байта: `12`, `34`, `56`, `78`. Поэтому в отладчике, дампах памяти и цветах всё пишут в hex.

В C++:

```cpp
int a = 0b1101;        // двоичный литерал: 13
int b = 0xFF;          // шестнадцатеричный: 255
int c = 0b1111'0000;   // разделители работают и здесь: 240

std::println("{:b}", 13);      // 1101
std::println("{:08b}", 13);    // 00001101: 8 разрядов, с ведущими нулями
std::println("{:x}", 255);     // ff
std::println("{:#010x}", 255); // 0x000000ff
```

## Побитовые операторы

Побитовые операторы работают с каждым битом числа отдельно.

| Оператор | Название | Правило для каждого бита |
|---|---|---|
| `a & b` | И (AND) | 1, если **оба** бита 1 |
| `a \| b` | ИЛИ (OR) | 1, если **хотя бы один** бит 1 |
| `a ^ b` | Исключающее ИЛИ (XOR) | 1, если биты **разные** |
| `~a` | НЕ (NOT) | Каждый бит переворачивается |
| `a << n` | Сдвиг влево | Биты сдвигаются влево на `n`, справа приходят нули |
| `a >> n` | Сдвиг вправо | Биты сдвигаются вправо на `n` |

```
    1100 (12)        1100 (12)        1100 (12)       ~ 0000 1100 (12)
  & 1010 (10)      | 1010 (10)      ^ 1010 (10)       = 1111 0011
  = 1000 (8)       = 1110 (14)      = 0110 (6)
```

> [!warning] Не путай с логическими операторами
> `&&` и `||` — **логические**: работают с истинностью целых значений. `&` и `|` — **побитовые**: работают с отдельными битами. `5 && 2` — это `true` (оба не ноль), а `5 & 2` — это `0` (`101 & 010`).

### Сдвиги

Сдвиг влево на `n` умножает на 2ⁿ, сдвиг вправо делит на 2ⁿ (для неотрицательных чисел):

```cpp
int x = 5;        // 0000 0101
int y = x << 3;   // 0010 1000 = 40 = 5 * 8
int z = y >> 2;   // 0000 1010 = 10 = 40 / 4
```

`1u << n` — число, у которого установлен только бит номер `n`. Это главный строительный блок для масок.

> [!ub] Ловушки сдвигов
> - Сдвиг на число бит **больше или равное** размеру типа — UB: `1u << 32` для 32-битного `unsigned int`.
> - Сдвиг влево, при котором единица уходит в знаковый бит или дальше у **знакового** типа, исторически был UB. С C++20 правила смягчили, но лучше просто не сдвигать знаковые числа.
>
> Правило: **для битовых операций используй беззнаковые типы** (`unsigned int`, `std::uint32_t`, `std::uint8_t`).

## Битовые флаги

Представь состояние персонажа: на земле, в воде, невидим, отравлен, горит, оглушён… Можно завести 6 переменных `bool` (6 байт). А можно хранить их в **одном** числе, по биту на флаг:

```cpp
#include <cstdint>
#include <print>

// Каждый флаг — число с одним установленным битом
constexpr std::uint32_t FlagOnGround  = 1u << 0;   // ...0001
constexpr std::uint32_t FlagInWater   = 1u << 1;   // ...0010
constexpr std::uint32_t FlagInvisible = 1u << 2;   // ...0100
constexpr std::uint32_t FlagPoisoned  = 1u << 3;   // ...1000
constexpr std::uint32_t FlagBurning   = 1u << 4;

int main() {
    std::uint32_t state = 0;                 // все флаги сброшены

    state |= FlagOnGround;                   // УСТАНОВИТЬ флаг
    state |= FlagPoisoned | FlagBurning;     // установить сразу несколько
    std::println("Состояние: {:05b}", state);              // 11001

    state &= ~FlagBurning;                   // СБРОСИТЬ флаг
    std::println("Потушили:  {:05b}", state);              // 01001

    state ^= FlagInvisible;                  // ПЕРЕКЛЮЧИТЬ флаг
    std::println("Невидим:   {:05b}", state);              // 01101

    bool poisoned = (state & FlagPoisoned) != 0;           // ПРОВЕРИТЬ флаг
    std::println("Отравлен: {}", poisoned);                // true

    // Проверить, что установлены ВСЕ флаги из набора
    constexpr std::uint32_t danger = FlagPoisoned | FlagInWater;
    bool inDanger = (state & danger) == danger;
    std::println("Отравлен и в воде: {}", inDanger);       // false
}
```

Запомни четыре идиомы, они встречаются в любом движке:

| Действие | Код |
|---|---|
| Установить | `flags \|= mask;` |
| Сбросить | `flags &= ~mask;` |
| Переключить | `flags ^= mask;` |
| Проверить | `(flags & mask) != 0` |

> [!deep] Почему `flags &= ~mask` сбрасывает флаг
> `~mask` переворачивает все биты маски: там, где был единственный бит 1, теперь 0, а везде остальное — единицы. AND с этим числом оставляет все биты `flags` как есть (AND с 1 не меняет бит), кроме одного, который обнуляется (AND с 0 всегда 0).
> ```
>   flags     = 1 1 0 0 1
>   mask      = 1 0 0 0 0
>   ~mask     = 0 1 1 1 1
>   flags & ~mask = 0 1 0 0 1
> ```

> [!engine] Флаги и маски в движках
> - **Слои коллизий**: каждый объект принадлежит слою (бит), и у него есть маска «с какими слоями я сталкиваюсь». Пуля игрока проверяет `(enemy.layer & bullet.collisionMask) != 0`. Так устроены слои в Unity, Unreal, Box2D.
> - **ECS**: набор компонентов сущности хранится как битовая маска. Система «физика» ищет сущности, у которых `(mask & (Position | Velocity)) == (Position | Velocity)`. Мы сделаем это в модуле 13.
> - **Состояния рендера**: включён ли тест глубины, смешивание, отсечение граней — тоже флаги.
>
> Выгода не только в памяти: проверить 32 условия можно **одной** инструкцией процессора.

## Упаковка цвета RGBA

Цвет пикселя обычно хранится как 4 компоненты по байту (0…255): красный (R), зелёный (G), синий (B) и прозрачность (A, alpha). Четыре байта — ровно 32 бита, одно `std::uint32_t`:

```
 бит:   31      24 23      16 15       8 7        0
       [   R    ] [   G    ] [   B    ] [   A    ]
```

```cpp
#include <cstdint>
#include <print>

int main() {
    std::uint8_t r = 255, g = 128, b = 0, a = 255;   // оранжевый, непрозрачный

    // УПАКОВКА: сдвигаем каждую компоненту на её место и объединяем через |
    std::uint32_t color = (std::uint32_t{r} << 24) | (std::uint32_t{g} << 16)
                        | (std::uint32_t{b} << 8)  |  std::uint32_t{a};
    std::println("Цвет: {:#010x}", color);    // 0xff8000ff

    // РАСПАКОВКА: сдвигаем нужный байт в младшие разряды и отрезаем маской 0xFF
    auto red   = static_cast<std::uint8_t>((color >> 24) & 0xFF);
    auto green = static_cast<std::uint8_t>((color >> 16) & 0xFF);
    auto blue  = static_cast<std::uint8_t>((color >> 8)  & 0xFF);
    auto alpha = static_cast<std::uint8_t>( color        & 0xFF);
    std::println("R={} G={} B={} A={}", red, green, blue, alpha);
}
```

Почему `std::uint32_t{r} << 24`, а не просто `r << 24`? Вспомни **целочисленное продвижение** из прошлого урока: `r` превратится в знаковый `int`, и сдвиг 255 на 24 бита залезет в знаковый бит. Сначала явно расширяем до беззнакового 32-битного типа, потом сдвигаем.

> [!engine] Порядок каналов
> Порядок компонент в 32-битном числе — договорённость, а не закон. Встречаются RGBA, ARGB, BGRA, ABGR. Когда в модуле 07 мы будем выводить наш framebuffer в окно через WinAPI, окажется, что Windows ждёт пиксели в порядке **BGRA** (в памяти: синий, зелёный, красный, неиспользуемый байт). Перепутаешь, и красные стены станут синими. Это классический первый баг любого самописного рендерера.

## Маски и битовые поля

Маска с несколькими единицами вырезает **группу** бит. Например, клетку карты можно упаковать в 16 бит:

```
 бит:  15        9   8   7   6  5           0
      [ не занято ] [S] [ R ] [  тип (0-63) ]
```

- биты 0–5: тип клетки (64 варианта);
- биты 6–7: поворот (0°, 90°, 180°, 270°);
- бит 8: проходима ли (`solid`).

```cpp
std::uint16_t packTile(unsigned type, unsigned rotation, bool solid) {
    return static_cast<std::uint16_t>((type & 0x3F) | ((rotation & 0x3) << 6) | ((solid ? 1u : 0u) << 8));
}

unsigned tileType(std::uint16_t tile)     { return tile & 0x3F; }
unsigned tileRotation(std::uint16_t tile) { return (tile >> 6) & 0x3; }
bool     tileSolid(std::uint16_t tile)    { return (tile >> 8) & 0x1; }
```

`0x3F` = `11 1111` (6 единиц), `0x3` = `11` (2 единицы). Маской `& 0x3F` мы отрезаем всё, кроме 6 младших бит. (Функции мы разберём в модуле 02; здесь важна битовая арифметика.)

> [!engine] Зачем так экономить
> Карта 1024 × 1024 клетки — миллион клеток. По 2 байта — 2 МБ, по структуре из `int`, `int` и `bool` (12 байт с выравниванием) — 12 МБ. Чем компактнее данные, тем больше их помещается в кэш процессора и тем быстрее их обход. Тот же принцип в сетевом коде: каждый бит в пакете, который отправляется 60 раз в секунду 64 игрокам, на счету.

## Трюки со степенями двойки

Степени двойки в двоичной записи — одна единица: `8` = `1000`, `64` = `100 0000`. Отсюда несколько полезных приёмов (для беззнаковых `x`):

| Задача | Выражение | Почему работает |
|---|---|---|
| `x` — степень двойки? | `x != 0 && (x & (x - 1)) == 0` | `1000 & 0111` = 0. У не-степени есть ещё единицы. |
| `x % 16` | `x & 15` | Остаток от деления на 2ⁿ — это младшие `n` бит. |
| `x / 16` | `x >> 4` | |
| Округлить `x` **вверх** до кратного 16 | `(x + 15) & ~15u` | Прибавили «почти 16», обнулили младшие 4 бита. |

Последний трюк понадобится нам в модуле 12 при написании аллокаторов: адрес нового объекта нужно **выровнять** вверх до кратного 8 или 16.

> [!deep] Компилятор знает эти трюки
> Не нужно вручную заменять `x / 16` на `x >> 4` ради скорости: для беззнаковых чисел оптимизатор сделает это сам. Пиши так, как понятнее. Трюки нужны там, где компилятор не может догадаться: когда делитель — переменная, про которую **ты** знаешь, что она степень двойки.

## Заголовок `<bit>`

С C++20 многие битовые операции есть готовыми, и компилятор превращает их в одну специальную инструкцию процессора:

| Функция | Пример | Результат |
|---|---|---|
| `std::popcount(x)` | `std::popcount(0b1011u)` | `3`: сколько единиц |
| `std::has_single_bit(x)` | `std::has_single_bit(64u)` | `true`: степень двойки? |
| `std::bit_ceil(x)` | `std::bit_ceil(100u)` | `128`: ближайшая степень двойки сверху |
| `std::bit_floor(x)` | `std::bit_floor(100u)` | `64` |
| `std::countr_zero(x)` | `std::countr_zero(8u)` | `3`: сколько нулей справа (номер младшей единицы) |
| `std::countl_zero(x)` | `std::countl_zero(1u)` | `31`: сколько нулей слева |
| `std::rotl(x, n)` | | Циклический сдвиг влево |
| `std::bit_cast<T>(x)` | | Переосмыслить байты как другой тип (было в [[01.2 Переменные и фундаментальные типы#Как число лежит в памяти|уроке 01.2]]) |

Функции работают только с **беззнаковыми** типами: компилятор не даст передать `int`.

## Как хранятся отрицательные числа

Знаковые целые хранятся в **дополнительном коде** (two's complement). С C++20 это гарантировано стандартом. Правило: чтобы получить `-x`, нужно перевернуть все биты `x` и прибавить 1.

```
  5  = 0000 0101
 ~5  = 1111 1010
 ~5 + 1 = 1111 1011 = -5
```

Следствия, которые стоит запомнить:
- **`-1` — это все единицы**: `0xFFFFFFFF` для 32 бит. Поэтому `static_cast<unsigned>(-1)` = 4 294 967 295.
- **Старший бит — знак**: 1 у отрицательных.
- **`~x == -x - 1`**: `~5` = −6.
- Диапазон несимметричен: `int` от −2 147 483 648 до **2 147 483 647**. У минимального числа нет положительной пары, и `-INT_MIN` — переполнение.

> [!deep] Зачем такая странная схема
> Дополнительный код хорош тем, что **сложение одно и то же** для знаковых и беззнаковых чисел: процессору не нужны отдельные схемы. `0xFFFFFFFF + 1` даёт 0 (перенос за 32-й бит отбрасывается), и это правильно и для беззнаковых (4 294 967 295 + 1 = 2³², по модулю 0), и для знаковых (−1 + 1 = 0). Различаются только сравнения, деление и сдвиг вправо.

Сдвиг вправо отрицательного числа в C++20 определён как **арифметический**: старший (знаковый) бит размножается, и `-8 >> 1` = `-4`. Для беззнаковых сдвиг вправо **логический**: слева всегда приходят нули.

> 2. Возьми цвет `0x3366CCFF`. Вытащи из него компоненты и напечатай их. Затем сделай цвет на 50% темнее: раздели R, G и B пополам (alpha не трогай) и собери обратно.

> [!interview] Вопрос с собеседования
