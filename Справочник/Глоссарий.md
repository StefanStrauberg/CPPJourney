# Глоссарий

Термины курса в алфавитном порядке. В скобках — английский вариант (его ты встретишь в документации и сообщениях об ошибках). Глоссарий пополняется с каждым модулем.

---

**AddressSanitizer (ASan)** — инструмент, который встраивает в программу проверки обращений к памяти и ловит выходы за границы и обращения к освобождённой памяти. Подключим в модуле 03.

**Big-endian / little-endian** — порядок байт многобайтового числа в памяти. x86/x64 — little-endian: младший байт по меньшему адресу. → [[01.2 Переменные и фундаментальные типы]]

**COMDAT** — секция объектного файла, из нескольких одинаковых копий которой линковщик оставляет одну. Так реализован `inline`. → [[02.5 Многофайловые программы и линковщик]]

**CRT (C Runtime)** — библиотека времени выполнения C и C++: код запуска программы, куча, ввод-вывод. → [[00.2 Как исходник становится программой]]

**Data-driven design** — подход, при котором поведение программы задаётся данными (таблицы, файлы уровней), а не кодом. → [[Практикум 01 — Основы]]

**Debug / Release** — конфигурации сборки: для отладки (без оптимизаций, с проверками) и для скорости. → [[00.2 Как исходник становится программой]]

**ODR (One Definition Rule)** — правило одного определения: каждая функция и переменная определяется в программе ровно один раз. → [[02.5 Многофайловые программы и линковщик]]

**PDB** — файл отладочной информации MSVC: связь машинного кода с исходником, имена и расположение переменных. → [[00.6 Отладчик — главный инструмент]]

**RVO (Return Value Optimization)** — оптимизация, при которой возвращаемый объект строится сразу в памяти вызывающей функции, без копирования. → [[02.1 Функции]]

**SIMD** — инструкции процессора, обрабатывающие несколько чисел за раз. Подробно в модуле 11.

**SSO (Small String Optimization)** — хранение короткой строки прямо внутри объекта `std::string`, без выделения памяти в куче. В MSVC до 15 символов. → [[01.6 Ввод, вывод, строки и случайность]]

---

**Агрегатная инициализация** (aggregate initialization) — инициализация полей структуры списком в фигурных скобках по порядку: `Enemy e{"Imp", 60};`. → [[01.7 Первые составные типы — array, vector, struct]]

**Аргумент** (argument) — значение, переданное в функцию при вызове. Сравни: **параметр**. → [[02.1 Функции]]

**Бюджет кадра** (frame budget) — время на один кадр: 16,7 мс при 60 FPS. → [[00.1 Что такое C++ и почему движки пишут на нём]]

**Висячая ссылка / висячий указатель** (dangling reference / pointer) — ссылка на уже уничтоженный объект. Обращение через неё — UB. → [[02.3 Ссылки и передача параметров]]

**Внешнее / внутреннее связывание** (external / internal linkage) — видно ли имя из других единиц трансляции. → [[02.5 Многофайловые программы и линковщик]]

**Время жизни** (lifetime, storage duration) — промежуток работы программы, когда объект существует: автоматическое, статическое, динамическое, потоковое. → [[02.4 Области видимости, время жизни и пространства имён]]

**Встраивание** (inlining) — подстановка тела функции на место вызова оптимизатором. → [[02.2 Как работает вызов — стек и рекурсия]]

**Выравнивание** (alignment) — требование, чтобы данные лежали по адресам, кратным их размеру; из-за него в структурах появляется заполнение. → [[01.7 Первые составные типы — array, vector, struct]]

**Генератор сборки** — роль CMake: он не компилирует сам, а создаёт файлы для системы сборки (MSBuild, Ninja). → [[00.4 CMake с нуля]]

**Декорирование имён** (name mangling) — кодирование типов параметров и пространств имён в имени символа: `?square@@YAHH@Z`. → [[00.2 Как исходник становится программой]]

**Дополнительный код** (two's complement) — способ хранения отрицательных целых: `-x = ~x + 1`. → [[01.4 Биты и байты]]

**Единица трансляции** (translation unit) — один `.cpp` после работы препроцессора; компилируется независимо от остальных. → [[00.2 Как исходник становится программой]]

**Заполнение** (padding) — пустые байты, которые компилятор вставляет в структуру ради выравнивания полей. → [[01.7 Первые составные типы — array, vector, struct]]

**Затенение** (shadowing) — объявление во внутреннем блоке имени, совпадающего с внешним. → [[02.4 Области видимости, время жизни и пространства имён]]

**Зерно** (seed) — начальное значение генератора случайных чисел; одинаковое зерно даёт одинаковую последовательность. → [[01.6 Ввод, вывод, строки и случайность]]

**Кадр стека** (stack frame) — область стека одного вызова функции: адрес возврата, локальные переменные, сохранённые регистры. → [[02.2 Как работает вызов — стек и рекурсия]]

**Куча** (heap) — область памяти для объектов произвольного времени жизни. Подробно в модуле 03.

**Линковщик** (linker) — программа, собирающая объектные файлы и библиотеки в исполняемый файл и связывающая ссылки на символы с их определениями. → [[00.2 Как исходник становится программой]]

**Неопределённое поведение** (undefined behavior, UB) — ситуация, для которой стандарт не определяет результат; может случиться что угодно. → [[00.1 Что такое C++ и почему движки пишут на нём]]

**Область видимости** (scope) — часть кода, где доступно имя. Сравни: **время жизни**. → [[02.4 Области видимости, время жизни и пространства имён]]

**Объектный файл** (object file, `.obj`) — результат компиляции одной единицы трансляции: машинный код и таблица символов. → [[00.2 Как исходник становится программой]]

**Объявление / определение** (declaration / definition) — «такое есть» / «вот оно целиком». Объявлений сколько угодно, определение одно. → [[02.1 Функции]]

**Параметр** (parameter) — переменная в объявлении функции, получающая значение аргумента. → [[02.1 Функции]]

**Перегрузка** (overloading) — несколько функций с одним именем и разными параметрами. → [[02.1 Функции]]

**Предварительное объявление** (forward declaration) — `struct Enemy;`: сообщить, что тип существует, без его определения. → [[02.5 Многофайловые программы и линковщик]]

**Предсказание ветвлений** (branch prediction) — угадывание процессором направления условного перехода; ошибка стоит 15–20 тактов. → [[01.5 Управление потоком]]

**Препроцессор** (preprocessor) — текстовый этап до компиляции: обрабатывает `#include`, `#define`, `#if`. → [[00.2 Как исходник становится программой]]

**Пресет** (preset) — именованный набор настроек CMake в `CMakePresets.json`. → [[00.4 CMake с нуля]]

**Пространство имён** (namespace) — именованная область для имён, защищающая от конфликтов: `ember::Vec2`. → [[02.4 Области видимости, время жизни и пространства имён]]

**Сужающее преобразование** (narrowing conversion) — преобразование с потерей данных (`double` → `int`). Запрещено в `{}`-инициализации. → [[01.2 Переменные и фундаментальные типы]]

**Ссылка** (reference) — псевдоним существующего объекта: `int& r = x;`. → [[02.3 Ссылки и передача параметров]]

**Стек вызовов** (call stack) — область памяти потока с кадрами всех незавершённых вызовов функций. 1 МБ у главного потока в Windows. → [[02.2 Как работает вызов — стек и рекурсия]]

**Структурная привязка** (structured binding) — `auto [a, b] = f();`: распаковка полей в переменные. → [[02.1 Функции]]

**Требования использования** (usage requirements) — свойства цели CMake (`PUBLIC`/`INTERFACE`), которые передаются зависящим целям. → [[02.6 CMake — библиотеки и структура проекта]]

**Цель** (target) — то, что собирает CMake: программа или библиотека со своими свойствами. → [[00.4 CMake с нуля]]

**Целочисленное продвижение** (integral promotion) — автоматическое расширение типов меньше `int` до `int` в арифметике. → [[01.3 Операторы, выражения и преобразования]]

**Хвостовой вызов** (tail call) — вызов функции последним действием; оптимизатор может превратить такую рекурсию в цикл. → [[02.2 Как работает вызов — стек и рекурсия]]

**Хэндл** (handle) — номер объекта (плюс поколение) вместо прямого указателя; движки используют хэндлы, чтобы ссылки не висели. Подробно в модуле 12.
