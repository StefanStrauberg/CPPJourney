# 03.2 Указатели

> [!abstract] О чём урок
> - **указатель** — переменная, которая хранит адрес;
> - операторы `&` (взять адрес) и `*` (разыменовать), стрелка `->`;
> - `nullptr` и указатель как «необязательная ссылка»;
> - `const` и указатели: четыре комбинации и как их читать;
> - `void*` и указатель на указатель;
> - полный ответ на вопрос «чем указатель отличается от ссылки».

## Указатель — переменная с адресом

```cpp
#include <print>

int main() {
    int health = 100;
    int* ptr = &health;           // ptr хранит адрес health

    std::println("health = {}", health);
    std::println("ptr    = {}", static_cast<const void*>(ptr));   // сам адрес
    std::println("*ptr   = {}", *ptr);                            // значение по адресу

    *ptr -= 30;                   // изменить health через указатель
    std::println("health = {}", health);   // 70

    int armor = 50;
    ptr = &armor;                 // указатель можно перенаправить на другую переменную
    *ptr += 10;
    std::println("armor = {}, health = {}", armor, health);   // 60, 70
}
```

```
health = 100
ptr    = 0x5a8eaff6f4
*ptr   = 100
health = 70
armor = 60, health = 70
```

(Адрес у тебя будет другим и будет меняться от запуска к запуску, вспомни ASLR.)

Три новых элемента синтаксиса:

| Запись | Где | Значение |
|---|---|---|
| `int*` | в объявлении типа | «указатель на `int`» |
| `&health` | в выражении | **взять адрес**: получить указатель на `health` |
| `*ptr` | в выражении | **разыменовать**: обратиться к тому, на что указывает `ptr` |

Указатель — самостоятельная переменная. У неё есть свой адрес и свой размер: **8 байт** на x64, независимо от того, на что она указывает (`sizeof(int*) == sizeof(double*) == sizeof(Enemy*) == 8`). Внутри — просто 64-битное число.

```
     health                         ptr
   ┌────────┐                   ┌──────────────────┐
   │   70   │ ◄─────────────────│ 0x5a8eaff6f4     │
   └────────┘                   └──────────────────┘
  адрес 0x5a8eaff6f4              адрес 0x5a8eaff6e8
```

> [!warning] Один символ — два смысла
> `*` и `&` в C++ перегружены смыслами, и это сбивает с толку:
> - `int* p` (в объявлении) — «`p` это указатель»; `*p` (в выражении) — «то, на что указывает `p`»; `a * b` — умножение.
> - `int& r` (в объявлении) — «`r` это ссылка»; `&x` (в выражении) — «адрес `x`»; `a & b` — побитовое И.
>
> Смотри на контекст: объявление это или выражение.

> [!warning] Ловушка объявления
> ```cpp
> int* a, b;    // a — указатель, а b — ОБЫЧНЫЙ int!
> ```
> Звёздочка относится к имени, а не к типу. Правило: **одно объявление указателя на строку**. Звёздочку в курсе пишем рядом с типом (`int* a`), как принято в C++-сообществе: так видно, что тип переменной — «указатель на int».

## Печать указателей

Почему `static_cast<const void*>(ptr)`, а не просто `std::println("{}", ptr)`? `std::format` умеет печатать только указатели типа `void*` и `const void*` (и `nullptr`). Для `int*` форматтера нет, и код не скомпилируется. Так сделано намеренно: указатель на `char` в C традиционно означает строку, и библиотека не хочет гадать, адрес ты хочешь напечатать или текст. Явное приведение к `const void*` говорит: «мне нужен адрес».

## `nullptr` — указатель в никуда

Указатель, который ни на что не указывает, равен **`nullptr`**:

```cpp
int* target = nullptr;

if (target != nullptr) {    // или короче: if (target)
    *target = 0;
}
```

Разыменование `nullptr` — неопределённое поведение. На практике программа падает с `0xC0000005`, потому что нулевая страница памяти не отображена ([[03.1 Карта памяти процесса#Защита страниц и нулевой указатель|урок 03.1]]).

> [!warning] `NULL` и `0`
> В старом коде вместо `nullptr` пишут `NULL` или просто `0`. Это наследие C: `NULL` — макрос, равный нулю, то есть **целое число**, а не указатель, и это иногда ломает выбор перегрузки функции. `nullptr` (C++11) — настоящий «нулевой указатель» своего собственного типа. Пиши только `nullptr`.

> [!ub] Неинициализированный указатель
> ```cpp
> int* p;      // мусорный адрес
> *p = 5;      // запись по случайному адресу
> ```
> Неинициализированный указатель хуже нулевого: он указывает **куда-то**. Запись через него может молча испортить любые данные программы. Компилятор предупреждает (`C4700`), но не всегда может это заметить. Правило то же, что для всех переменных: **инициализируй сразу**, хотя бы `nullptr`.

## Указатели на структуры: стрелка

```cpp
#include <print>
#include <string>
#include <vector>

struct Enemy {
    std::string name;
    int health = 100;
};

// Найти самого слабого врага. Если врагов нет, вернуть nullptr.
Enemy* findWeakest(std::vector<Enemy>& enemies) {
    Enemy* weakest = nullptr;
    for (Enemy& e : enemies) {
        if (weakest == nullptr || e.health < weakest->health) {
            weakest = &e;
        }
    }
    return weakest;
}

int main() {
    std::vector<Enemy> wave = {{"Imp", 60}, {"Demon", 150}, {"Zombie", 40}};

    Enemy* target = findWeakest(wave);
    if (target != nullptr) {
        target->health -= 50;                  // то же, что (*target).health -= 50
        std::println("Добиваем {}: осталось {}", target->name, target->health);
    }

    std::vector<Enemy> empty;
    if (findWeakest(empty) == nullptr) {
        std::println("Врагов нет, стрелять не в кого");
    }
}
```

```
Добиваем Zombie: осталось -10
Врагов нет, стрелять не в кого
```

`target->health` — короткая запись для `(*target).health`: «поле `health` объекта, на который указывает `target`». Скобки в длинной форме нужны, потому что у `.` приоритет выше, чем у `*`.

Этот пример показывает главное применение указателя в современном C++: **необязательная ссылка**. Функция говорит: «вот враг, а может, и никого». Ссылка так не умеет, нулевых ссылок не бывает.

> [!compare] Go и C#
> - **Go**: указатели почти такие же: `var p *int = &x`, `*p = 5`, `nil`. Но в Go нет `->`: `p.health` работает и для указателя, компилятор разыменовывает сам. И нет арифметики указателей ([[03.3 Массивы и арифметика указателей|следующий урок]]).
> - **C#**: переменная класса — по сути указатель, который язык прячет: `Enemy e = null; e.Health` — это `NullReferenceException`. Настоящие указатели в C# есть только в `unsafe`-коде.
> - **Python**: указателей нет, все имена — ссылки на объекты.

## Указатель или ссылка?

| | Ссылка `T&` | Указатель `T*` |
|---|---|---|
| Может быть «пустой» | нет | да, `nullptr` |
| Можно перенаправить | нет | да |
| Нужно инициализировать | обязательно | желательно |
| Синтаксис доступа | как к самому объекту: `r.health` | `*p`, `p->health` |
| Арифметика | нет | есть (следующий урок) |
| Свой адрес и размер | обычно нет (это псевдоним) | да, 8 байт |

Правило выбора в параметрах функций:
- объект **обязан** существовать → **ссылка** (`Enemy&` или `const Enemy&`);
- объекта **может не быть** → **указатель** (`Enemy*`), и `nullptr` означает «нет».

```cpp
// Ссылка: цель обязательна. Указатель: бонусного оружия может не быть.
void attack(Enemy& target, const Weapon* bonusWeapon) {
    int damage = 10;
    if (bonusWeapon != nullptr) {
        damage += bonusWeapon->damage;
    }
    target.health -= damage;
}

attack(imp, nullptr);        // без бонуса
attack(imp, &plasmaGun);     // с бонусом
```

## `const` и указатели

С указателем связаны **два** объекта: сам указатель и то, на что он указывает. Каждый может быть константным:

```cpp
int health = 100;
int armor = 50;

const int* a = &health;         // указатель на КОНСТАНТНЫЙ int
*a = 5;                         // ошибка: нельзя менять то, на что указывает
a = &armor;                     // можно: сам указатель не константный

int* const b = &health;         // КОНСТАНТНЫЙ указатель на int
*b = 5;                         // можно
b = &armor;                     // ошибка: указатель нельзя перенаправить

const int* const c = &health;   // нельзя ни то, ни другое
```

**Как читать:** справа налево, от имени. `int* const b` — «`b` — константный указатель на `int`». `const int* a` — «`a` — указатель на `int`, который константный». Чтобы не путаться, запомни: `const` **левее** `*` защищает данные, `const` **правее** `*` защищает сам указатель.

На практике чаще всего нужен `const T*`: «покажу тебе объект, но менять его нельзя». Это указательный аналог `const T&`.

## `void*` и указатель на указатель

**`void*`** — указатель «на что-то», без типа. Его нельзя разыменовать (неизвестно, сколько байт читать и как их понимать), но в него можно положить любой указатель на данные. Встречается в низкоуровневом коде: функции работы с памятью (`memcpy`, урок 03.6), WinAPI, аллокаторы. Чтобы снова получить типизированный указатель, нужно явное приведение:

```cpp
int value = 42;
void* raw = &value;                        // неявно: любой T* превращается в void*
int* typed = static_cast<int*>(raw);       // обратно — только явно
```

**Указатель на указатель** — переменная, которая хранит адрес другого указателя:

```cpp
int health = 100;
int* p = &health;
int** pp = &p;      // pp указывает на p
**pp = 50;          // health = 50
```

В C это основной способ «вернуть указатель через параметр». В C++ для этого есть ссылка на указатель (`int*& p`) или просто возвращаемое значение. Но `T**` ты увидишь в WinAPI и Direct3D: функции создания объектов вроде `D3D11CreateDevice(..., ID3D11Device** device, ...)` возвращают созданный объект именно так. В модуле 19 мы это встретим.

## Под капотом

> [!deep] Разыменование — это инструкция чтения памяти
> Для процессора указатель — обычное 64-битное число в регистре. Разыменование превращается в инструкцию, которая читает или пишет память **по этому адресу**:
> ```cpp
> int readHealth(const int* p) { return *p; }
> ```
> ```asm
> mov  eax, DWORD PTR [rcx]   ; rcx = p (первый аргумент), читаем 4 байта по адресу p
> ret
> ```
> Квадратные скобки в ассемблере означают «память по адресу». `p->health` при `health`, лежащем со смещением 32 от начала структуры, станет `[rcx+32]`. Поля структуры — это просто смещения.
>
> Тип указателя существует **только для компилятора**: он определяет, сколько байт читать (4 для `int`, 8 для `double`) и как их понимать. В машинном коде `int*` и `float*` неотличимы.

> [!engine] Указатели в движках
> Старые движки (и сегодняшние, в низкоуровневых частях) состоят из указателей: объекты сцены ссылаются друг на друга, компоненты хранят указатель на владельца, ресурсы раздаются указателями. Это быстро, но хрупко: удалили объект, а указатель на него остался у десятка других. Отсюда два направления, которые мы изучим:
> - **владение** (модули 04–05): у каждого объекта есть ровно один владелец, который его удаляет, а остальные только «смотрят»;
> - **хэндлы** (модуль 12): вместо указателя хранят номер объекта, который можно проверить на актуальность.

> [!try] Попробуй сам
> 1. Объяви `double speed = 5.5;` и указатель на неё. Напечатай `sizeof(speed)`, `sizeof(&speed)` и `sizeof(*(&speed))`.
> 2. Напиши функцию `void swapViaPointers(int* a, int* b)`, которая меняет значения местами. Вызови её. Что нужно передать в качестве аргументов?
> 3. Попробуй напечатать `int*` без приведения к `const void*`. Прочитай ошибку компилятора.
> 4. Объяви `const int* p` и попробуй изменить значение через него. Затем объяви `int* const q` и попробуй его перенаправить. Запиши коды ошибок.
> 5. Разыменуй `nullptr` в Debug под отладчиком (`F5`). Что показал отладчик и на какой строке остановился?

> [!quiz]- Проверь себя
> 1. Что хранит указатель? Сколько он занимает на x64?
> 2. Что делают `&x` и `*p` в выражениях?
> 3. Какие переменные объявлены в строке `int* a, b;`?
> 4. Чем `const int* p` отличается от `int* const p`?
> 5. Когда в параметре функции использовать указатель, а когда ссылку?
> 6. Почему `std::println` не печатает `int*` напрямую?
> 7. Что будет при разыменовании `nullptr`? А неинициализированного указателя?
>
> > [!success]- Ответы
> > 1. Адрес объекта в памяти. 8 байт, независимо от типа объекта.
> > 2. `&x` — получить адрес `x` (указатель на `x`). `*p` — обратиться к объекту, на который указывает `p`.
> > 3. `a` — указатель на `int`, `b` — обычный `int`.
> > 4. `const int* p` — нельзя менять данные через `p`, но можно перенаправить `p`. `int* const p` — можно менять данные, но нельзя перенаправить указатель.
> > 5. Ссылка — если объект обязан существовать. Указатель — если объекта может не быть (`nullptr` означает «нет»).
> > 6. `std::format` форматирует только `void*`/`const void*`, чтобы не путать адреса со строками (`char*`). Нужно явное `static_cast<const void*>`.
> > 7. Неопределённое поведение. С `nullptr` на практике почти гарантированное падение `0xC0000005`. С мусорным указателем — что угодно, включая тихую порчу данных.

> [!interview] Вопрос с собеседования
> **«Чем указатель отличается от ссылки?»** Теперь полный ответ: указатель — самостоятельный объект с адресом; его можно не инициализировать, перенаправить, обнулить, у него есть арифметика, можно взять указатель на указатель. Ссылка — псевдоним: обязана быть инициализирована, не перенаправляется, не бывает нулевой (без UB), нельзя сделать массив ссылок или ссылку на ссылку. На уровне машинного кода обе обычно реализуются как адрес. Хороший ответ заканчивается правилом выбора: ссылка для обязательного объекта, указатель для необязательного.
