# 03.3 Массивы и арифметика указателей

> [!abstract] О чём урок
> - встроенные массивы C и почему они «распадаются» в указатели;
> - **арифметика указателей**: `p + 1`, `p[i]`, разность указателей;
> - обход массива парой указателей «начало–конец» (основа итераторов);
> - передача массива в функцию: указатель + размер и `std::span`;
> - буфер пикселей и шаг строки;
> - C-строки: `const char*` и завершающий ноль;
> - аргументы командной строки: `argc` и `argv`.

## Встроенные массивы

В [[01.7 Первые составные типы — array, vector, struct#Встроенные массивы в стиле C|уроке 01.7]] мы отложили встроенные массивы «до указателей». Пришло время.

```cpp
int damage[5] = {10, 25, 40, 15, 30};
```

Это пять `int` подряд в памяти, 20 байт, без каких-либо служебных данных: ни размера, ни ёмкости, просто байты. `std::array<int, 5>` устроен внутри точно так же: это структура, в которой лежит именно такой массив.

## Массив распадается в указатель

Имя массива почти в любом выражении **неявно превращается** в указатель на его первый элемент. Это называется **распад** (array-to-pointer decay):

```cpp
#include <iterator>
#include <print>

int main() {
    int damage[5] = {10, 25, 40, 15, 30};
    int* p = damage;                 // распад: p указывает на damage[0]

    std::println("{} {}", *p, damage[0]);        // 10 10
    std::println("{} {}", *(p + 2), p[2]);       // 40 40

    std::println("&damage[0] = {}", static_cast<const void*>(&damage[0]));
    std::println("&damage[1] = {}", static_cast<const void*>(&damage[1]));
    std::println("Элементов от [0] до [4]: {}", &damage[4] - &damage[0]);

    std::println("Размер массива: {} байт, элементов: {}", sizeof(damage), std::size(damage));
    std::println("Размер указателя: {} байт", sizeof(p));
}
```

```
10 10
40 40
&damage[0] = 0x6e3e4ff8e0
&damage[1] = 0x6e3e4ff8e4
Элементов от [0] до [4]: 4
Размер массива: 20 байт, элементов: 5
Размер указателя: 8 байт
```

Обрати внимание на адреса: соседние элементы отличаются на **4** — размер `int`.

## Арифметика указателей

К указателю можно прибавлять и вычитать целые числа, и это работает **в элементах, а не в байтах**:

| Выражение | Смысл |
|---|---|
| `p + n` | указатель на элемент, стоящий на `n` позиций дальше; адрес увеличивается на `n * sizeof(T)` |
| `p - n` | на `n` позиций раньше |
| `++p`, `--p` | сдвинуть на один элемент |
| `q - p` | сколько **элементов** между указателями (тип `std::ptrdiff_t`) |
| `p[n]` | ровно то же самое, что `*(p + n)` |

Последняя строка — ключ ко всему: **оператор `[]` для указателя определён через арифметику**. `damage[2]` — это «распасться в указатель, сдвинуться на 2 элемента, разыменовать».

> [!deep] Под капотом: масштабирование адреса
> Процессоры x86 умеют умножать индекс на 1, 2, 4 или 8 прямо при обращении к памяти. Поэтому `p[i]` для `int*` компилируется в одну инструкцию:
> ```asm
> mov  eax, DWORD PTR [rcx + rdx*4]   ; rcx = p, rdx = i, 4 = sizeof(int)
> ```
> Арифметика указателей в C появилась именно потому, что прямо отображается на такую адресацию. Отсюда же и формула для двумерных данных `y * width + x`: процессор считает её за пару инструкций.

> [!tip] Курьёз
> Раз `a[i]` — это `*(a + i)`, а сложение коммутативно, то `i[a]` — это `*(i + a)`, то есть то же самое. `2[damage]` компилируется и равно 40. Никогда так не пиши, но на собеседовании такой вопрос иногда задают, чтобы проверить понимание.

## Обход парой указателей

Массив можно обойти, не используя индексы вообще: указатель на начало и указатель **за последний элемент**:

```cpp
int total = 0;
const int* end = damage + 5;           // указывает ЗА последний элемент
for (const int* it = damage; it != end; ++it) {
    total += *it;
}
```

Указатель «за конец» (one-past-the-end) — особый: его **можно** вычислять и сравнивать, но **нельзя** разыменовывать. Так устроены все диапазоны в C++: полуинтервал `[begin, end)`. На этой идее построены **итераторы** стандартной библиотеки (модуль 06), а `for` по диапазону внутри разворачивается ровно в такой цикл.

> [!ub] За пределы массива
> - Вычислить указатель дальше, чем на один элемент за концом (или раньше начала), — уже UB, даже без разыменования.
> - Разыменовать указатель за концом — UB.
> - Сравнивать `<`/`>` указатели на **разные** массивы — результат не определён (на практике сравнит адреса, но полагаться нельзя).

## Массивы и функции

Если передать массив в функцию, он распадается в указатель, и **размер теряется**:

```cpp
void printAll(int values[]) {         // на самом деле параметр — int* values
    // sizeof(values) == 8: размер указателя, а не массива!
}
```

Запись `int values[]` в параметре — обман: компилятор молча заменяет её на `int* values`. Внутри функции узнать, сколько элементов в массиве, **невозможно**. Отсюда классический стиль C: передавать указатель **и размер**:

```cpp
int sum(const int* values, std::size_t count) {
    int total = 0;
    for (std::size_t i = 0; i < count; ++i) {
        total += values[i];
    }
    return total;
}

sum(damage, 5);   // размер передаём вручную — и можем ошибиться
```

### `std::span` — указатель и размер в одном

C++20 добавил `std::span` из заголовка `<span>`: лёгкий **вид** (view) на непрерывный кусок памяти. Внутри — ровно указатель и размер, 16 байт, но вместе:

```cpp
#include <array>
#include <print>
#include <span>
#include <vector>

int sum(std::span<const int> values) {    // принимает всё, что лежит в памяти подряд
    int total = 0;
    for (int v : values) {
        total += v;
    }
    return total;
}

int main() {
    int raw[] = {1, 2, 3};
    std::array<int, 4> fixed = {10, 20, 30, 40};
    std::vector<int> dynamic = {100, 200};

    std::println("{} {} {}", sum(raw), sum(fixed), sum(dynamic));          // 6 100 300
    std::println("{}", sum(std::span(dynamic.data(), 1)));                // 100: только первый элемент
}
```

`std::span` не владеет данными (ничего не выделяет и не освобождает), копируется бесплатно и знает свой размер. **Передавай `std::span` вместо пары «указатель + размер»** везде, где функции нужен кусок массива. Подробнее в модуле 06.

> [!engine] Виды на память в движках
> В движках идея «указатель + размер» повсюду: буфер вершин, массив пикселей текстуры, кусок файла в памяти. В Unreal для этого есть `TArrayView`, в нашем движке будет `std::span`. Функции движка, которые только **читают** набор данных, принимают вид и не заботятся о том, где эти данные живут: в векторе, в статическом массиве или в памяти, отображённой из файла.

## Буфер пикселей и шаг строки

Картинка — это массив пикселей, строка за строкой. Пиксель `(x, y)` находится по индексу `y * width + x` (ты уже видел эту формулу в [[Практикум 02 — Функции и первый кирпич движка#Задание 5. Сапёр ⭐⭐⭐|Сапёре]]). Указатель на начало строки `y` — `pixels + y * width`:

```cpp
#include <cstdint>
#include <print>
#include <vector>

int main() {
    constexpr int width = 16;
    constexpr int height = 6;
    std::vector<std::uint32_t> framebuffer(width * height, 0);   // всё чёрное

    // Нарисовать прямоугольник: строки 1..4, столбцы 3..12
    for (int y = 1; y <= 4; ++y) {
        std::uint32_t* row = framebuffer.data() + y * width;     // начало строки y
        for (int x = 3; x <= 12; ++x) {
            row[x] = 0xFFFF0000;                                 // красный (ARGB)
        }
    }

    // «Показать» буфер символами
    for (int y = 0; y < height; ++y) {
        const std::uint32_t* row = framebuffer.data() + y * width;
        for (int x = 0; x < width; ++x) {
            std::print("{}", row[x] != 0 ? '#' : '.');
        }
        std::println("");
    }
}
```

```
................
...##########...
...##########...
...##########...
...##########...
................
```

Это и есть наш будущий рендер: в модуле 07 вместо символов `#` и `.` буфер отправится в окно Windows, и каждое число станет цветным пикселем.

> [!deep] Шаг строки (pitch)
> Здесь строка занимает ровно `width` пикселей. Но в реальных графических API строки часто **длиннее**, чем нужно: видеокарта выравнивает начало каждой строки, скажем, на 256 байт. Расстояние в байтах между началами соседних строк называется **шагом** (pitch или stride), и правильная формула — `base + y * pitch + x * bytesPerPixel`. Если перепутать pitch с `width * 4`, картинка получится «скошенной». Классическая ошибка, мы встретим её в Direct3D.

## C-строки

Строка в стиле C — это массив `char`, который заканчивается **нулевым символом** `'\0'`:

```cpp
const char* name = "Imp";
```

```
   name ──►  'I'  'm'  'p'  '\0'
```

Строковый литерал `"Imp"` имеет тип `const char[4]`: три буквы и завершающий ноль, лежит в области констант ([[03.1 Карта памяти процесса#Области памяти процесса|урок 03.1]]). Вот почему в практикуме 00 «сто» было `const char[7]`: 6 байт UTF-8 и ноль.

Длины у C-строки нет: её **ищут**, шагая по символам до нуля. Так работает стандартная функция `std::strlen` из `<cstring>`:

```cpp
std::size_t myStrlen(const char* text) {
    const char* p = text;
    while (*p != '\0') {
        ++p;
    }
    return static_cast<std::size_t>(p - text);   // разность указателей
}
```

> [!warning] Почему мы пользуемся `std::string`
> - Длина C-строки вычисляется проходом по всей строке, а `std::string::size()` хранится готовой.
> - Буфер C-строки нужно выделять самому и не ошибиться с размером (не забыть место под ноль!).
> - Функции копирования `strcpy`, `strcat` не проверяют размер буфера. Копирование длинного имени в `char name[16]` молча перепишет соседнюю память — **переполнение буфера**, источник половины уязвимостей в истории программирования. MSVC даже помечает эти функции как небезопасные (предупреждение `C4996`).
>
> Но C-строки никуда не денутся: их принимает WinAPI, их возвращают многие библиотеки. Метод `std::string::c_str()` даёт `const char*` на содержимое строки, с завершающим нулём.

## Аргументы командной строки

Теперь можно разобрать вторую форму `main`:

```cpp
#include <print>

int main(int argc, char* argv[]) {
    std::println("Аргументов: {}", argc);
    for (int i = 0; i < argc; ++i) {
        std::println("argv[{}] = {}", i, argv[i]);
    }
}
```

- `argc` (argument count) — количество аргументов;
- `argv` (argument vector) — массив C-строк. `argv[0]` — путь к самой программе, дальше аргументы, которые передали при запуске.

Запусти из терминала VS Code (в папке `practice`):

```powershell
.\build\bin\Debug\m03_args.exe --level e1m1 --god
```

```
Аргументов: 4
argv[0] = .\build\bin\Debug\m03_args.exe
argv[1] = --level
argv[2] = e1m1
argv[3] = --god
```

Чтобы передавать аргументы при запуске по `F5`, допиши их в `.vscode/launch.json`: `"args": ["--level", "e1m1", "--god"]`.

> [!engine] Командная строка движка
> Движки и игры активно используют аргументы командной строки: `-windowed`, `-nosound`, `+map e1m1`, `-log`. Оригинальный Doom запускался с ключами вроде `-warp 1 1` (сразу на первую карту) и `-nomonsters`. В нашем движке аргументы будут разбираться при запуске и превращаться в настройки.
