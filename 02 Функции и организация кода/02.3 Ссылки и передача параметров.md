# 02.3 Ссылки и передача параметров

> [!abstract] О чём урок
> - что такое **ссылка** и чем она отличается от копии;
> - три способа передать параметр: по значению, по ссылке, по константной ссылке, и как выбирать;
> - почему `const&` может ссылаться на временное значение, а `&` — нет;
> - **висячие ссылки**: самая коварная ошибка этого урока;
> - под капотом: ссылка — это адрес, и что из этого следует для скорости.

## Ссылка — второе имя

```cpp
int health = 100;
int& alias = health;    // alias — ссылка на health: ДРУГОЕ ИМЯ той же переменной

alias -= 30;
std::println("{}", health);   // 70: изменили health через alias
```

`int&` читается как «ссылка на `int`». Ссылка — не новая переменная со своей памятью, а **псевдоним** уже существующей. Всё, что делается со ссылкой, делается с оригиналом.

Три правила ссылок:
1. **Ссылку нужно инициализировать** при объявлении: `int& r;` не скомпилируется. Ссылка «ни на что» не имеет смысла.
2. **Ссылку нельзя перенаправить.** После `int& r = a;` присваивание `r = b;` не делает `r` ссылкой на `b`, а **копирует значение** `b` в `a`.
3. **Нулевых ссылок не бывает.** Ссылка всегда ссылается на объект (если программа не нарушила правила и не вызвала UB).

```cpp
int a = 1;
int b = 2;
int& r = a;
r = b;          // a = 2. r по-прежнему ссылается на a!
b = 10;         // a не изменится: r не связана с b
```

> [!compare] Ссылки в других языках
> - **C#**: «ссылочные типы» (`class`) — совсем другое понятие: там переменная хранит ссылку на объект в куче, которую можно перенаправить и обнулить. Ближайший аналог ссылки C++ — параметры `ref` и `in`.
> - **Go**: ссылок нет, есть указатели (`*int`), которые можно перенаправить и которые бывают `nil`.
> - **Python**: все имена — ссылки на объекты, но присваивание перенаправляет имя, а не меняет объект.
> - **C++**: ссылка — неизменяемый псевдоним конкретного объекта. Указатели (как в Go) тоже есть, они в модуле 03.

## Передача параметров

### По значению: копия

```cpp
void heal(int health) {    // health — копия аргумента
    health += 50;
}
```

Функция получает **копию**. Изменения не видны снаружи. Для маленьких типов это быстро и безопасно.

### По ссылке: изменить аргумент

```cpp
#include <print>

void heal(int& health) {   // health — ссылка на аргумент
    health += 50;
}

int main() {
    int playerHealth = 20;
    heal(playerHealth);
    std::println("{}", playerHealth);   // 70
}
```

Функция получает **сам объект** и может его изменить. Используется, когда изменение аргумента — **смысл** функции: `applyDamage(enemy, 30)`, `shuffle(deck)`.

### По константной ссылке: без копии и без изменений

```cpp
int totalHealth(const std::vector<Enemy>& enemies) {
    int total = 0;
    for (const Enemy& e : enemies) {
        total += e.health;
    }
    return total;
}
```

`const std::vector<Enemy>&` — ссылка, через которую **нельзя** изменить объект. Функция получает доступ к оригиналу без копирования, а компилятор гарантирует, что она его не испортит. Попытка изменить что-то через `const&` — ошибка компиляции.

Это **самый частый** способ передачи больших объектов в C++: строк, векторов, структур.

> [!warning] Цена забытого `&`
> ```cpp
> int totalHealth(std::vector<Enemy> enemies);   // по значению!
> ```
> Работает правильно, но при **каждом** вызове копируется весь вектор: выделяется память, копируется каждый враг вместе со строкой-именем. Если функция вызывается каждый кадр для тысячи врагов, это тысячи выделений памяти в секунду на ровном месте. Самая частая ошибка производительности у людей, пришедших из C# и Java, где объекты передаются по ссылке автоматически.

### Как выбрать

| Тип параметра | Когда | Пример |
|---|---|---|
| `T` (по значению) | Маленькие типы: числа, `bool`, `char`, небольшие структуры (`Vec2`). Или когда функции всё равно нужна своя копия. | `float length(Vec2 v)` |
| `const T&` | Большие типы, только чтение: `std::string`, `std::vector`, крупные структуры | `void draw(const Map& map)` |
| `T&` | Функция должна **изменить** аргумент | `void applyDamage(Enemy& e, int dmg)` |

Граница «маленький/большой» — примерно **16 байт** и отсутствие динамической памяти внутри. `int`, `float`, `Vec2`, `Vec3` — по значению. `std::string` (32 байта плюс буфер в куче) — по `const&`, даже если строка короткая.

> [!tip] Возвращай результат, а не пиши его в параметр
> Иногда функции пишут результат в параметр-ссылку:
> ```cpp
> void computeBounds(const Map& map, int& width, int& height);   // «выходные» параметры
> ```
> Так делали в старом C++. Современный стиль — **возвращать** результат, при необходимости структурой: `Bounds computeBounds(const Map& map);`. Вызов `auto [w, h] = computeBounds(map);` читается лучше, а копирования нет благодаря RVO ([[02.1 Функции#Несколько результатов|урок 02.1]]).

## Ссылки и временные значения

Неконстантная ссылка может ссылаться только на **настоящую переменную**, а не на временное значение:

```cpp
void heal(int& health);

heal(playerHealth);   // ок
heal(50);             // ошибка: 50 — временное значение, его нечего «изменять»
heal(a + b);          // ошибка: результат a + b — тоже временный
```

Логика простая: функция с `int&` собирается **изменить** аргумент. Изменять число `50` бессмысленно: изменение никто не увидит.

А **константная** ссылка к временному значению привязаться может:

```cpp
void printName(const std::string& name);

printName("Doomguy");   // ок: создаётся временная std::string, ссылка указывает на неё
```

Временная строка живёт до конца выражения с вызовом, то есть ровно столько, сколько работает функция. Поэтому `const std::string&` — универсальный параметр для строк: принимает и переменные, и литералы.

## Ссылки в циклах: напоминание

То же самое правило работает в `for` по диапазону ([[01.7 Первые составные типы — array, vector, struct#Цикл for по диапазону — копия или сам элемент|урок 01.7]]):

```cpp
for (Enemy e : enemies)         // копия каждого врага (медленно, изменения теряются)
for (Enemy& e : enemies)        // сам враг, можно менять
for (const Enemy& e : enemies)  // сам враг, только чтение — выбор по умолчанию
```

И в структурных привязках:

```cpp
auto& [x, y] = playerPosition;  // x и y — ссылки на поля playerPosition
x += 1.0f;                      // меняет playerPosition.x
```

## Висячие ссылки

Ссылка не продлевает жизнь объекта. Если объект уничтожен, а ссылка на него осталась, она **висит** (dangling reference), и обращение через неё — неопределённое поведение.

### Не возвращай ссылку на локальную переменную

```cpp
#include <print>
#include <string>

const std::string& makeTitle(const std::string& name) {
    std::string title = "Sir " + name;
    return title;       // title умирает при выходе из функции!
}

int main() {
    const std::string& t = makeTitle("Doomguy");
    std::println("{}", t);   // UB: t ссылается на уничтоженную строку
}
```

MSVC предупреждает: `C4172: возвращаемый адрес локальной переменной или временного`. Исправление простое: **возвращай по значению** (`std::string makeTitle(...)`). Благодаря RVO это не дороже.

> [!ub] Ссылка на элемент вектора
> Есть ловушка коварнее:
> ```cpp
> std::vector<Enemy> enemies = {imp, demon};
> Enemy& first = enemies[0];
> enemies.push_back(baron);    // вектор мог перевыделить буфер!
> first.health -= 10;          // UB: first ссылается на освобождённую память
> ```
> Помнишь, как растёт вектор ([[01.7 Первые составные типы — array, vector, struct#Вектор — динамический массив|урок 01.7]])? Когда `push_back` упирается в `capacity`, вектор переезжает в новый буфер, а старый освобождает. Все ссылки на элементы старого буфера становятся висячими. Иногда код «работает» (если перевыделения не было), иногда портит память. В Debug-сборке MSVC такую ошибку часто удаётся поймать по магическому значению `0xDDDDDDDD` в освобождённой памяти ([[00.6 Отладчик — главный инструмент#Магические числа MSVC|урок 00.6]]).
>
> **Правило:** не держи ссылки на элементы вектора, пока вектор может изменить размер.

> [!engine] Почему движки не хранят ссылки на объекты
> Это настолько частая проблема, что в движках объекты редко хранят прямые ссылки (и указатели) друг на друга. Вместо этого используют **хэндлы**: номер объекта в массиве плюс «поколение». Если объект удалён или массив переехал, хэндл просто перестаёт быть действительным, и это можно **проверить**. Мы построим систему хэндлов в модуле 12.

## Под капотом

> [!deep] Ссылка — это адрес
> На уровне машинного кода передать по ссылке — значит передать **адрес** объекта (8 байт на x64). Функция `void heal(int& health)` получает в регистре RCX адрес переменной, а `health += 50` превращается в «прочитать 4 байта по адресу из RCX, прибавить 50, записать обратно».
>
> Отсюда два следствия:
> 1. **Для маленьких типов передача по значению быстрее**, чем по ссылке. `int` по значению лежит прямо в регистре, а по ссылке функция должна сходить в память по адресу. Поэтому `const int&` вместо `int` — не оптимизация, а скорее наоборот.
> 2. **Совмещение (aliasing).** Получив две ссылки, компилятор не знает, не указывают ли они на **один и тот же** объект:
>    ```cpp
>    void addTwice(int& total, const int& bonus) {
>        total += bonus;
>        total += bonus;   // нужно ли перечитывать bonus из памяти? А вдруг он и есть total?
>    }
>    ```
>    Если вызвать `addTwice(x, x)`, `bonus` изменится после первой строки. Поэтому компилятор обязан перечитывать `bonus` из памяти после каждой записи в `total`, и часть оптимизаций становится невозможной. В горячих циклах движков это иногда заметно; у MSVC есть нестандартное ключевое слово `__restrict`, которым программист обещает, что совмещения нет. К этой теме мы вернёмся в модуле 11.

> [!try] Попробуй сам
> 1. Напиши `void swapValues(int& a, int& b)`, которая меняет значения двух переменных местами. Проверь на двух переменных. (В стандартной библиотеке есть готовая `std::swap`.)
> 2. Напиши `void normalizeHealth(std::vector<int>& healths, int maxHealth)`, которая ограничивает каждое значение диапазоном `[0, maxHealth]`.
> 3. Попробуй вызвать `heal(50)` с параметром `int&`. Прочитай ошибку компилятора.
> 4. Скомпилируй пример с `makeTitle` и найди предупреждение C4172. Запусти в Debug и в Release. Что напечаталось?
> 5. Вызови `addTwice(x, x)` при `x = 1`. Какой результат? А `addTwice(x, y)` при `x = 1, y = 1`?

> [!quiz]- Проверь себя
> 1. Что произойдёт: `int a = 1, b = 2; int& r = a; r = b; b = 5;` Чему равны `a`, `b`?
> 2. Как передать в функцию `std::string`, чтобы не копировать её и не позволить изменить?
> 3. Почему `void f(int& x); f(5);` не компилируется, а `void g(const int& x); g(5);` компилируется?
> 4. Как передавать `Vec2` (два `float`): по значению или по `const&`? Почему?
> 5. Почему опасно хранить `Enemy& e = enemies[0];` и потом вызывать `enemies.push_back(...)`?
> 6. Что не так с функцией `const std::string& getName() { std::string n = "Imp"; return n; }`?
>
> > [!success]- Ответы
> > 1. `a = 2`, `b = 5`. `r = b` скопировало значение `b` в `a`; ссылка `r` по-прежнему связана с `a`.
> > 2. `const std::string&`.
> > 3. Неконстантная ссылка не может ссылаться на временное значение (изменять его бессмысленно). Константная может: временное значение живёт до конца выражения.
> > 4. По значению: 8 байт передаются в регистре, а ссылка заставила бы функцию обращаться к памяти.
> > 5. При перевыделении буфера вектора ссылка станет висячей, и обращение через неё — неопределённое поведение.
> > 6. Возвращается ссылка на локальную переменную, которая уничтожается при выходе из функции: висячая ссылка. Нужно возвращать `std::string` по значению.

> [!interview] Вопрос с собеседования
> **«Чем ссылка отличается от указателя?»** Ответ (полностью — после модуля 03): ссылку нужно инициализировать, её нельзя перенаправить, она не бывает нулевой, у неё нет своей арифметики, и синтаксически она используется как сам объект. Указатель — самостоятельная переменная с адресом, которую можно менять, обнулять и сдвигать. На уровне машинного кода и то и другое обычно — адрес.
