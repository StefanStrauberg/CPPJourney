## Зачем функции

В «Арене» из [[Практикум 01 — Основы|практикума 01]] кусок «прочитать число от 1 до 3 с проверкой» занимал 8 строк, а в «Угадай число» такой кусок встречался дважды. Функция даёт куску кода **имя** и позволяет вызывать его откуда угодно:

```cpp
int action = readInt(1, 3);
```

Функции нужны:
- чтобы **не повторяться**: исправил баг в одном месте — исправил везде;
- чтобы **дать имя** идее: `applyDamage(enemy, 30)` читается лучше, чем три строки арифметики;
- чтобы **разбить** большую задачу на маленькие, каждую из которых можно понять и проверить отдельно.

## Синтаксис

```cpp
тип_результата имя(параметры) {
    тело
    return результат;
}
```

```cpp
#include <print>

// Урон с учётом брони: броня поглощает часть урона, но не меньше 1 единицы проходит всегда
int computeDamage(int baseDamage, int armor) {
    int damage = baseDamage - armor;
    if (damage < 1) {
        damage = 1;
    }
    return damage;
}

// Функция, которая ничего не возвращает: тип void
void printHit(int damage) {
    std::println("Попадание! Урон: {}", damage);
}

int main() {
    int dmg = computeDamage(30, 12);   // вызов: аргументы 30 и 12
    printHit(dmg);                     // Попадание! Урон: 18
    printHit(computeDamage(5, 50));    // Попадание! Урон: 1
}
```

- **Параметры** — переменные в объявлении функции (`baseDamage`, `armor`). **Аргументы** — значения, переданные при вызове (`30`, `12`).
- `return` завершает функцию и возвращает значение. В функции `void` можно писать `return;` без значения, чтобы выйти досрочно.
- Функция, которая обещала вернуть значение (не `void`), **обязана** это сделать на любом пути выполнения.

> [!ub] Забытый `return`
> ```cpp
> int sign(int x) {
>     if (x > 0) return 1;
>     if (x < 0) return -1;
>     // при x == 0 функция «падает» с конца без return
> }
> ```
> Выход из функции, которая должна вернуть значение, без `return` — неопределённое поведение. MSVC предупреждает: `C4715: не все пути к коду возвращают значение`. Не игнорируй это предупреждение.

## Объявление и определение

В C++ функцию нужно **объявить до того, как вызвать**. Компилятор читает файл сверху вниз, и, встретив вызов неизвестной функции, выдаёт ошибку `C3861: идентификатор не найден` (ты видел её в [[Практикум 00 — Инструменты#Задание 6. Под капотом своими руками ⭐⭐⭐|практикуме 00]]).

Если хочется написать `main` в начале файла, а вспомогательные функции после, используй **объявление** (прототип):

```cpp
#include <print>

int computeDamage(int baseDamage, int armor);   // объявление: только «подпись», с ; вместо тела

int main() {
    std::println("{}", computeDamage(30, 12));   // компилятор уже знает подпись
}

int computeDamage(int baseDamage, int armor) {  // определение: подпись + тело
    return baseDamage > armor ? baseDamage - armor : 1;
}
```

- **Объявление** (declaration) сообщает: «такая функция существует, вот её параметры и тип результата».
- **Определение** (definition) — объявление вместе с телом.
- Объявлений может быть сколько угодно, а определение — **ровно одно** во всей программе.

Это различие — основа многофайловых программ: объявления живут в заголовочных файлах, определения в `.cpp`. Подробно в [[02.5 Многофайловые программы и линковщик|уроке 02.5]].

> [!compare] Порядок функций в других языках
> В **C#**, **Go** и **Python** функции можно вызывать в любом порядке: компилятор (или интерпретатор) видит весь файл или пакет целиком. **C++** унаследовал от C однопроходную модель: всё должно быть объявлено выше места использования.

## Параметры передаются по значению

```cpp
#include <print>

void heal(int health) {
    health += 50;           // меняется КОПИЯ
}

int main() {
    int playerHealth = 20;
    heal(playerHealth);
    std::println("{}", playerHealth);   // 20: ничего не изменилось!
}
```

По умолчанию параметр — это **новая переменная**, инициализированная копией аргумента. Функция работает со своей копией, и оригинал не меняется. Для `int` это именно то, что нужно. А для `std::vector` на миллион элементов копирование при каждом вызове — катастрофа. Как изменять аргументы и передавать большие объекты без копирования, разберём в [[02.3 Ссылки и передача параметров|уроке 02.3]].

## Несколько результатов

Функция возвращает одно значение. Если нужно несколько, верни **структуру**:

```cpp
#include <print>

struct AttackResult {
    int damage = 0;
    bool critical = false;
    bool killed = false;
};

AttackResult attack(int baseDamage, int targetHealth, bool lucky) {
    AttackResult result;
    result.critical = lucky;
    result.damage = lucky ? baseDamage * 2 : baseDamage;
    result.killed = result.damage >= targetHealth;
    return result;
}

int main() {
    // Структурная привязка (C++17): распаковать поля в отдельные переменные
    auto [damage, critical, killed] = attack(25, 40, true);
    std::println("Урон {}, крит: {}, убит: {}", damage, critical, killed);
}
```

`auto [a, b, c] = ...` — **структурная привязка** (structured binding): переменные получают значения полей по порядку. Для двух значений есть готовый тип `std::pair` из `<utility>`, для большего числа — `std::tuple` из `<tuple>`. Но поля структуры с осмысленными именами читаются лучше, чем `.first` и `.second`.

> [!compare] Несколько результатов
> - **Go**: `func attack() (int, bool)` и `damage, crit := attack()`. Встроено в язык.
> - **C#**: кортежи `(int damage, bool crit) Attack()` и `var (d, c) = Attack();`.
> - **Python**: `return damage, crit` и `d, c = attack()`.
> - **C++**: структура (или `std::pair`/`std::tuple`) плюс структурная привязка.

> [!deep] Под капотом: возврат структуры не копирует её
> Может показаться, что `return result;` копирует структуру из функции наружу. На деле компилятор применяет **RVO** (Return Value Optimization): ещё до вызова он выделяет место под результат в кадре **вызывающей** функции и передаёт его адрес скрытым параметром. Функция строит `result` сразу там, и копирования нет вовсе. С C++17 для `return Тип{...};` это гарантировано стандартом. Поэтому возвращать большие структуры и даже векторы из функций **нормально**: это не медленно.

## Перегрузка

Несколько функций могут иметь одно имя, если различаются **параметры**:

```cpp
#include <print>
#include <string>

void show(int value)                { std::println("[int] {}", value); }
void show(float value)              { std::println("[float] {:.2f}", value); }
void show(const std::string& text)  { std::println("[text] {}", text); }

int main() {
    show(42);                     // [int] 42
    show(3.14159f);               // [float] 3.14
    show(std::string("Ready"));   // [text] Ready
}
```

> [!warning] Почему не `log`
> Сначала я назвал эти функции `log` и получил ошибку компиляции `C2556`: «перегруженная функция отличается от `float log(float)` только возвращаемым типом». Оказалось, в **глобальном** пространстве имён уже есть функция `log` (натуральный логарифм) из библиотеки C: её подтянули стандартные заголовки. Библиотека C не знает о пространствах имён и складывает всё в глобальное. Это хороший аргумент за то, чтобы держать свой код в собственном пространстве имён ([[02.4 Области видимости, время жизни и пространства имён|урок 02.4]]).

Компилятор выбирает функцию по типам аргументов. Это **разрешение перегрузки** (overload resolution). Правила сложные, но идея простая: лучше всего подходит точное совпадение, хуже — совпадение после продвижения (`char` → `int`), ещё хуже — после преобразования (`double` → `int`).

> [!warning] Неоднозначность
> ```cpp
> void show(int value);
> void show(float value);
>
> show(2.5);   // ошибка: 2.5 — это double; в int и во float — одинаково «плохие» преобразования
> ```
> Компилятор не может выбрать и выдаёт `C2668: неоднозначный вызов перегруженной функции`. Исправить можно, уточнив аргумент: `show(2.5f)`.

> [!deep] Под капотом: перегрузка — это разные имена
> Помнишь декорированные имена из [[00.2 Как исходник становится программой#Что внутри .obj|урока 00.2]]? Для линковщика три функции `show` — это три **разных** символа: `?show@@YAXH@Z` (int), `?show@@YAXM@Z` (float) и третий, с длинным именем для строки. Перегрузка существует только на уровне языка; после компиляции от неё не остаётся следа.

Перегрузка **по типу результата** невозможна: функции `int f()` и `float f()` конфликтуют, ведь по вызову `f()` нельзя понять, какую выбрать.

## Аргументы по умолчанию

```cpp
void spawnEnemy(int x, int y, int health = 100, float speed = 1.0f);

spawnEnemy(5, 7);               // health = 100, speed = 1.0f
spawnEnemy(5, 7, 300);          // speed = 1.0f
spawnEnemy(5, 7, 300, 2.5f);
```

- Значения по умолчанию можно давать только **последним** параметрам.
- Пропускать аргумент в середине нельзя: `spawnEnemy(5, 7, , 2.5f)` — ошибка.
- Если у функции есть отдельное объявление, значения по умолчанию пишутся **в объявлении**, а не в определении.

## `[[nodiscard]]`

Некоторые функции бессмысленно вызывать, игнорируя результат:

```cpp
[[nodiscard]] int computeDamage(int baseDamage, int armor);

computeDamage(30, 12);   // предупреждение C4834: возвращаемое значение отброшено
```

Атрибут `[[nodiscard]]` просит компилятор предупредить, если результат функции выбросили. Это ловит настоящие баги: например, в коде `clamp(health, 0, 100);` программист забыл присвоить результат обратно в `health`. Ставь `[[nodiscard]]` функциям, которые только вычисляют значение и не делают ничего другого.

## `constexpr`-функции

Функцию можно пометить `constexpr`. Тогда, если её аргументы известны при компиляции, компилятор **вычислит её сам**, а результат можно использовать там, где нужна константа:

```cpp
constexpr int tilesToPixels(int tiles) {
    return tiles * 32;
}

constexpr int screenWidth = tilesToPixels(40);   // 1280, вычислено при компиляции
std::array<int, tilesToPixels(2)> buffer{};      // размер массива: 64
```

С обычными (не константными) аргументами `constexpr`-функция работает как обычная. Подробно о вычислениях при компиляции поговорим в модуле 10.

## Практический пример — функция readInt

Соберём защищённое чтение числа из [[01.6 Ввод, вывод, строки и случайность#Что если ввели не число|урока 01.6]] в функцию:

```cpp
#include <iostream>
#include <limits>
#include <print>

// Читает целое число из диапазона [min, max]. Повторяет запрос, пока ввод неверный.
// Если ввод закончился (Ctrl+Z), возвращает min.
int readInt(int min, int max) {
    int value = 0;
    while (!(std::cin >> value) || value < min || value > max) {
        if (std::cin.eof()) {
            return min;
        }
        std::cin.clear();
        std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
        std::print("Нужно число от {} до {}: ", min, max);
    }
    return value;
}

int main() {
    std::print("Сложность (1-3): ");
    int difficulty = readInt(1, 3);

    std::print("Сколько ботов (0-15): ");
    int bots = readInt(0, 15);

    std::println("Сложность {}, ботов {}", difficulty, bots);
}
```

Код ввода теперь пишется один раз, а каждое место использования — одна строка. В практикуме мы перенесём `readInt` в отдельный файл и будем подключать его во всех консольных играх.

## Какой должна быть хорошая функция

- **Делает одну вещь**, и её имя говорит, какую. `computeDamage`, `isWalkable`, `drawMap`. Если имя приходится составлять через «и» (`loadAndDrawMap`), функцию стоит разделить.
- **Короткая**: помещается на экран. Если длиннее, скорее всего, внутри прячутся ещё функции.
- **Имя — глагол** для действий (`spawn`, `update`, `draw`) и вопрос для проверок (`isAlive`, `hasKey`, `canMove`).
- По возможности **чистая**: результат зависит только от параметров, и функция ничего не меняет вокруг. Такие функции легко тестировать и безопасно вызывать откуда угодно, в том числе из разных потоков (модуль 14).

> [!engine] Функции в движке
> - В движке есть **горячий код** (вызывается миллионы раз за кадр: математика векторов, обход частиц) и **холодный** (загрузка уровня, меню). Для горячего кода стоимость вызова имеет значение, и о ней следующий урок.
> - Хороший признак кода движка — множество маленьких чистых функций в математике и утилитах. Например, `lerp(a, b, t)` (линейная интерполяция) вызывается в анимациях, камере и интерфейсе тысячи раз за кадр. Её мы напишем в практикуме для библиотеки Ember.

> [!try] Попробуй сам
> 1. Напиши функцию `int clampInt(int value, int min, int max)` и проверь её на значениях внутри, ниже и выше диапазона. Затем пометь её `[[nodiscard]]` и вызови, не используя результат. Какое предупреждение выдал компилятор?
> 2. Напиши две перегрузки `area`: для круга (`float radius`) и для прямоугольника (`float width, float height`). Вызови `area(2)`. Что произошло и почему?
> 3. Напиши функцию `bool isLeapYear(int year)` (високосный: делится на 4, но не на 100, или делится на 400) и сделай её `constexpr`. Используй её в `static_assert(isLeapYear(2024));`: это проверка, которую выполняет компилятор.
> 4. Убери `return` из одной из веток функции `computeDamage` и посмотри на предупреждение.

> [!quiz]- Проверь себя
> 1. Чем объявление функции отличается от определения? Сколько может быть каждого?
> 2. Почему в C++ нельзя вызвать функцию, которая определена ниже по файлу, без предварительного объявления?
> 3. Функция `void f(int x) { x = 10; }` вызвана как `f(a)`. Изменится ли `a`?
> 4. Можно ли перегрузить функции, отличающиеся только типом результата?
> 5. Где писать значения аргументов по умолчанию, если есть отдельное объявление?
> 6. Зачем нужен `[[nodiscard]]`?
> 7. Копируется ли структура при `return result;`?
>
> > [!success]- Ответы
> > 1. Объявление — подпись функции (тип результата, имя, параметры) без тела. Определение — подпись с телом. Объявлений сколько угодно, определение ровно одно.
> > 2. Компилятор читает файл сверху вниз и к моменту вызова должен знать подпись функции, чтобы проверить аргументы и сгенерировать вызов.
> > 3. Нет, параметр передан по значению: функция изменила свою копию.
> > 4. Нет. По вызову нельзя определить, какой тип результата нужен.
> > 5. В объявлении.
> > 6. Чтобы компилятор предупреждал, когда результат функции проигнорирован: обычно это баг.
> > 7. Как правило, нет: компилятор применяет RVO и строит результат сразу в памяти вызывающей стороны.
