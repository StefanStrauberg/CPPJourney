# 00.5 Проект курса в VS Code

> [!abstract] О чём урок
> - создаём проект `practice/`, в котором будет жить весь код курса;
> - разбираем каждый файл: `CMakeLists.txt`, `CMakePresets.json`, настройки VS Code;
> - учимся **собирать** (`F7`), **запускать** (`Ctrl+Shift+F5`) и **отлаживать** (`F5`);
> - добавляем новую программу в проект;
> - разбираемся с кириллицей в консоли Windows.
>
> Урок практический: делай шаги параллельно с чтением.

## Шаг 1. Открываем папку проекта

1. В VS Code: **File → Open Folder…**
2. Перейди в папку курса `D:\SourceCode\CPPJourney`, создай в ней папку **`practice`** (кнопка «Создать папку» в диалоге) и выбери её.
3. VS Code спросит: *Do you trust the authors of the files in this folder?* Отвечай **Yes, I trust the authors**. Без доверия к папке расширения не смогут запускать CMake и компилятор.

> [!warning] Открывай именно `practice`, а не всю папку курса
> CMake Tools ищет `CMakeLists.txt` в **корне** открытой папки. Если открыть `CPPJourney`, он не найдёт проект (и заодно начнёт индексировать заметки Obsidian).

## Шаг 2. Структура проекта

Вот что у нас получится в конце урока:

```
practice/
├── .vscode/
│   ├── settings.json       ← настройки VS Code для этого проекта
│   └── launch.json         ← настройки отладки по F5
├── m00_setup/
│   ├── CMakeLists.txt      ← цели модуля 00
│   └── hello.cpp           ← первая программа
├── .gitignore
├── CMakeLists.txt          ← главный файл проекта
└── CMakePresets.json       ← пресеты: как конфигурировать и собирать
```

Создавать файлы и папки удобно в боковой панели **Explorer** (`Ctrl+Shift+E`): иконки «New File…» и «New Folder…» над деревом файлов. Чтобы создать файл сразу в подпапке, введи путь целиком: `m00_setup/hello.cpp`.

## Шаг 3. Главный CMakeLists.txt

Создай в корне `practice` файл `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.30)
project(CppJourney LANGUAGES CXX)

# ---------- Общие настройки для всех программ курса ----------

# Стандарт C++23, строго, без расширений компилятора
set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# Все .exe складываются в build/bin/<Debug|Release>/
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY ${CMAKE_BINARY_DIR}/bin)

if(MSVC)
    # /W4             — максимум полезных предупреждений
    # /permissive-    — строгое соответствие стандарту
    # /utf-8          — исходники и строки в UTF-8 (кириллица!)
    # /Zc:__cplusplus — честное значение макроса __cplusplus
    add_compile_options(/W4 /permissive- /utf-8 /Zc:__cplusplus)
endif()

# ---------- Модули курса ----------
add_subdirectory(m00_setup)
```

Каждая строка разобрана в [[00.4 CMake с нуля]]. С каждым новым модулем ты будешь добавлять в конец строку `add_subdirectory(...)`.

## Шаг 4. CMakePresets.json

Там же, в корне, создай `CMakePresets.json`:

```json
{
  "version": 6,
  "configurePresets": [
    {
      "name": "msvc",
      "displayName": "MSVC x64 (Visual Studio 2026)",
      "generator": "Visual Studio 18 2026",
      "architecture": "x64",
      "binaryDir": "${sourceDir}/build"
    }
  ],
  "buildPresets": [
    { "name": "debug",   "displayName": "Debug",   "configurePreset": "msvc", "configuration": "Debug" },
    { "name": "release", "displayName": "Release", "configurePreset": "msvc", "configuration": "Release" }
  ]
}
```

Один пресет конфигурации (`msvc`) и два пресета сборки (`debug` и `release`). `${sourceDir}` — макрос пресетов, означающий папку с `CMakeLists.txt`.

## Шаг 5. Первая программа

Создай папку `m00_setup`, а в ней два файла.

`m00_setup/CMakeLists.txt`:

```cmake
add_executable(m00_hello hello.cpp)
```

`m00_setup/hello.cpp`:

```cpp
#include <print>

int main() {
    std::println("Привет, C++!");
    std::println("Версия MSVC: {}, стандарт C++: {}", _MSC_VER, __cplusplus);
}
```

Пока не вникай в синтаксис, его мы разберём в [[01.1 Анатомия программы]]. Кратко: `std::println` печатает строку, а `{}` в ней заменяются на значения следующих аргументов (как `{0}` в C# `string.Format` или `{}` в Python `str.format`).

## Шаг 6. Настройки VS Code для проекта

Создай папку `.vscode` и в ней `settings.json`:

```json
{
    // --- CMake Tools ---
    "cmake.useCMakePresets": "always",
    "cmake.configureOnOpen": true,
    "cmake.buildBeforeRun": true,
    "cmake.options.statusBarVisibility": "visible",
    "cmake.debugConfig": {
        "console": "integratedTerminal"
    },

    // --- IntelliSense берёт настройки компиляции из CMake ---
    "C_Cpp.default.configurationProvider": "ms-vscode.cmake-tools",

    // --- Файлы ---
    "files.encoding": "utf8",
    "files.exclude": {
        "build": true
    },

    // --- Терминалы ---
    "terminal.integrated.defaultProfile.windows": "PowerShell",
    "terminal.integrated.profiles.windows": {
        "Developer PowerShell": {
            "path": "powershell.exe",
            "args": [
                "-NoExit",
                "-Command",
                "$env:PATH += ';C:\\Program Files (x86)\\Microsoft Visual Studio\\Installer'; & 'C:\\Program Files\\Microsoft Visual Studio\\18\\Community\\Common7\\Tools\\Launch-VsDevShell.ps1' -Arch amd64 -HostArch amd64 -SkipAutomaticLocation"
            ],
            "icon": "tools"
        }
    }
}
```

| Настройка | Зачем |
|---|---|
| `cmake.useCMakePresets: always` | Брать настройки из `CMakePresets.json`. |
| `cmake.configureOnOpen` | Конфигурировать проект сразу при открытии папки. |
| `cmake.buildBeforeRun` | Пересобирать программу перед каждым запуском. Без этого легко запустить старую версию и удивляться, почему изменения «не работают». |
| `cmake.options.statusBarVisibility` | Показывать кнопки CMake в строке состояния внизу окна. |
| `cmake.debugConfig.console` | При отладке программа работает во встроенном терминале, и в неё можно **вводить** данные с клавиатуры. |
| `C_Cpp.default.configurationProvider` | IntelliSense узнаёт от CMake стандарт C++, флаги и пути. Иначе он подчёркивает правильный код красным. |
| `files.exclude` | Скрыть папку `build` из дерева файлов: там тысячи служебных файлов. |
| `terminal.integrated.defaultProfile.windows` | В этом проекте терминал по умолчанию PowerShell: все команды курса написаны для него. |
| `terminal.integrated.profiles.windows` | Добавляет терминал **Developer PowerShell**, в котором доступны `cl`, `link`, `dumpbin`. |

> [!note] Если у тебя не Community-версия
> Путь в профиле Developer PowerShell рассчитан на Visual Studio **Community** 2026. Для Professional, Enterprise или Build Tools замени `Community` в пути на `Professional`, `Enterprise` или `BuildTools`.

Теперь `.vscode/launch.json`: он нужен, чтобы отладка запускалась привычной клавишей `F5`:

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Отладка (MSVC)",
            "type": "cppvsdbg",
            "request": "launch",
            "program": "${command:cmake.launchTargetPath}",
            "args": [],
            "cwd": "${workspaceFolder}",
            "console": "integratedTerminal"
        }
    ]
}
```

- `type: cppvsdbg` — отладчик Visual Studio (из расширения C/C++). Лучший отладчик для программ, собранных MSVC.
- `${command:cmake.launchTargetPath}` — CMake Tools подставит путь к `.exe` выбранной цели и **предварительно её соберёт**.

И последний файл, `.gitignore`, на случай, если будешь хранить проект в git (очень рекомендую):

```
build/
```

## Шаг 7. Конфигурация

Сохрани все файлы (`Ctrl+K S`). Если CMake Tools ещё не начал работу сам, перезагрузи окно: `Ctrl+Shift+P` → **Developer: Reload Window**.

1. Вверху появится список *Select a configure preset*. Выбери **MSVC x64 (Visual Studio 2026)**.
2. Внизу откроется панель **Output** с журналом CMake. Через несколько секунд там должно быть:

```
[cmake] -- The CXX compiler identification is MSVC 19.51.36260.0
...
[cmake] -- Configuring done
[cmake] -- Generating done
[cmake] -- Build files have been written to: D:/SourceCode/CPPJourney/practice/build
```

Если вместо этого красные ошибки, загляни в таблицу [[#Если что-то не работает]] в конце урока.

> [!warning] Отключи мешающие расширения
> Если у тебя установлены **Code Runner** или **C/C++ Runner**, сейчас самое время отключить их для этой папки: панель расширений (`Ctrl+Shift+X`) → шестерёнка у расширения → **Disable (Workspace)**. Подробности в [[00.3 Установка и проверка инструментов#Шаг 3. VS Code и расширения|уроке 00.3]].

## Шаг 8. Сборка, запуск, отладка

### Строка состояния

После конфигурации в строке состояния внизу окна появятся элементы CMake Tools. Примерно так (порядок может отличаться в зависимости от версии):

| Элемент | Что делает |
|---|---|
| `msvc` (configure-пресет) | Выбор пресета конфигурации |
| `Debug` (build-пресет) | Выбор конфигурации сборки: Debug или Release |
| ⚙ **Build** | Собрать |
| `[all]` | Какую цель собирать (по умолчанию все) |
| 🐞 | Отладка выбранной цели |
| ▶ | Запуск без отладки |
| `[m00_hello]` | **Цель для запуска и отладки** |

Те же действия есть в боковой панели **CMake** (иконка с треугольником в левой полосе) в разделе *Project Status*.

### Горячие клавиши

| Клавиши | Действие |
|---|---|
| `F7` | **Собрать** проект |
| `Ctrl+Shift+F5` | **Запустить** выбранную цель без отладки |
| `F5` | **Отлаживать** (через наш `launch.json`) |
| `Shift+F5` | Отлаживать через CMake Tools (если отладка не идёт) / **остановить** отладку (если идёт) |

Попробуй:

1. Нажми **`F7`**. В панели Output пробежит журнал MSBuild и в конце появится строка вида `m00_hello.vcxproj -> ...\build\bin\Debug\m00_hello.exe`. Значит, сборка удалась.
2. Нажми **`Ctrl+Shift+F5`**. Если VS Code спросит, какую цель запускать, выбери `m00_hello`. Во встроенном терминале появится:

```
Привет, C++!
Версия MSVC: 1951, стандарт C++: 202400
```

`1951` — внутренний номер версии компилятора (MSVC 19.51). `202400` — значение `__cplusplus` в режиме «самый свежий стандарт» (C++23 и новые возможности сверху).

3. Нажми **`F5`**. Программа запустится под отладчиком, отработает и завершится. Пока ничего интересного: отладчиком займёмся в [[00.6 Отладчик — главный инструмент|следующем уроке]].

> [!tip] Где ошибки
> Если сборка не удалась, ошибки появятся в панели **Problems** (`Ctrl+Shift+M`). Клик по ошибке переносит к строке кода. Но всегда полезно заглянуть и в **Output**: там полный текст ошибок, а Problems иногда показывает его обрезанным.

### Debug и Release

Конфигурация переключается щелчком по build-пресету (`Debug`) в строке состояния или в панели CMake: выбери `Release`, нажми `F7`, и программа соберётся в `build/bin/Release/`. В [[Практикум 00 — Инструменты|практикуме]] мы сравним, насколько они различаются.

## Шаг 9. Как добавить новую программу

Ты будешь делать это десятки раз, так что запомни порядок:

1. Создай файл, например `m00_setup/second.cpp`, и напиши в нём программу с функцией `main`.
2. Добавь в `m00_setup/CMakeLists.txt` строку:
   ```cmake
   add_executable(m00_second second.cpp)
   ```
3. Сохрани `CMakeLists.txt`: CMake Tools сам переконфигурирует проект.
4. Выбери новую цель для запуска: щелчок по `[m00_hello]` в строке состояния → `m00_second`.
5. `Ctrl+Shift+F5`.

> [!try] Попробуй сам
> Добавь программу `m00_second`, которая печатает три строки: твоё имя, «Учу C++» и любимую игру. Убедись, что можешь переключаться между `m00_hello` и `m00_second`.

> [!warning] В одной цели — одна функция `main`
> Каждая цель (программа) должна содержать ровно одну функцию `main`. Если добавить `second.cpp` в ту же `add_executable(m00_hello hello.cpp second.cpp)`, линковщик выдаст `LNK2005: main already defined`. Поэтому у каждой учебной программы своя цель.

## Шаг 10. IntelliSense: заглядываем в стандартную библиотеку

Расширение C/C++ понимает код и помогает его писать:

- **Наведи** мышь на `println`, и появится всплывающая подсказка с объявлением функции.
- `Ctrl+Space` — автодополнение.
- **`F12`** (или `Ctrl+Click`) на `std::println` — переход к определению. Откроется файл `print` из стандартной библиотеки MSVC: это обычный C++ код, только очень плотный. Стандартная библиотека — не магия, а код, который можно читать.
- Красная волнистая черта — IntelliSense видит ошибку ещё до компиляции.

> [!note] IntelliSense — не компилятор
> IntelliSense использует собственный анализатор кода, а не `cl.exe`. Иногда он ошибается в обе стороны: подчёркивает правильный код или пропускает ошибку. **Истину знает только компилятор**, то есть результат `F7`. Если IntelliSense ругается, а сборка проходит, попробуй `Ctrl+Shift+P` → **C/C++: Reset IntelliSense Database**.

## Шаг 11. Терминал Developer PowerShell

Открой панель терминала (`` Ctrl+` ``), нажми стрелку ⌄ рядом с кнопкой **+** и выбери **Developer PowerShell**. Появится приветствие `Visual Studio 2026 Developer PowerShell`. Проверь:

```powershell
cl
```

Теперь компилятор отвечает: `Microsoft (R) C/C++ Optimizing Compiler Version 19.51...`. В этом терминале мы будем заглядывать под капот: смотреть объектные файлы, ассемблер и зависимости программ. Первый раз уже в практикуме этого модуля.

## Кириллица в консоли Windows

Ты мог заметить, что в курсе для вывода используется `std::println`, а не `std::cout`, о котором пишут почти все учебники. Причина — кириллица.

> [!deep] Под капотом: почему `std::cout` печатает «кракозябры»
> Наш исходник в кодировке UTF-8, и флаг `/utf-8` говорит компилятору хранить строки в программе тоже в UTF-8. Буква «П» в UTF-8 занимает два байта: `D0 9F`.
>
> `std::cout` просто отправляет байты в консоль. А консоль Windows в русской локали по умолчанию считает, что байты пришли в кодировке **CP866** (досовская кодировка, наследие 1980-х). В CP866 байт `D0` — это символ `╨`, а `9F` — `Я`. В итоге
> ```cpp
> std::cout << "Привет, C++!\n";
> ```
> печатает `╨Я╤А╨╕╨▓╨╡╤В, C++!`.
>
> `std::println` (C++23) устроен умнее. Если вывод идёт в консоль, реализация MSVC **сама перекодирует** UTF-8 в UTF-16 и вызывает функцию WinAPI `WriteConsoleW`, которая печатает Unicode напрямую. Я проверил это в ассемблере: в Release-сборке `std::println` вызывает внутреннюю функцию `_Do_on_maybe_unicode_console`.
>
> Поэтому правило курса: **для вывода используем `std::println` / `std::print`**. `std::cout` мы тоже изучим (он встречается в любом чужом коде), но с кириллицей его лучше не смешивать.

> [!warning] А ввод?
> С **вводом** кириллицы из консоли (`std::cin`) та же проблема в обратную сторону: введённые русские буквы придут в программу в CP866, а не в UTF-8. Пока вводи с клавиатуры **латиницу и числа**. Когда будем работать с WinAPI, разберёмся, как это починить.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| CMake Tools не предлагает выбрать пресет | Проверь, что открыта папка `practice` (а не `CPPJourney`) и `CMakePresets.json` лежит в её корне. `Ctrl+Shift+P` → **CMake: Select Configure Preset**. |
| `Could not create named generator Visual Studio 18 2026` | CMake старше 4.2. Обнови CMake ([[00.3 Установка и проверка инструментов]]) и перезапусти VS Code. |
| `No CMAKE_CXX_COMPILER could be found` | Не установлена рабочая нагрузка C++ в Visual Studio. |
| Ошибка в `CMakePresets.json` | Проверь запятые и кавычки: JSON не прощает лишней или пропущенной запятой. |
| `F5` спрашивает, какой отладчик выбрать | Нет файла `.vscode/launch.json`, или он не в той папке. |
| Программа запускается, но изменений не видно | Сохрани файл (`Ctrl+S`)! Белая точка на вкладке файла означает несохранённые изменения. |
| Вылезла кнопка ▶ «Run Code» и ошибка про `g++` | Это Code Runner или C/C++ Runner, отключи их для рабочей области (шаг 7). |
| Всё сломалось непонятным образом | `Ctrl+Shift+P` → **CMake: Delete Cache and Reconfigure**. |

> [!quiz]- Проверь себя
> 1. Почему в VS Code нужно открывать папку `practice`, а не всю папку курса?
> 2. Что делает `${command:cmake.launchTargetPath}` в `launch.json`?
> 3. Ты добавил `fight.cpp` в `add_executable(m00_hello hello.cpp fight.cpp)`, и в обоих файлах есть `main`. Какая будет ошибка и на каком этапе?
> 4. Почему `std::cout << "Привет"` печатает мусор, а `std::println("Привет")` работает?
>
> > [!success]- Ответы
> > 1. CMake Tools ищет `CMakeLists.txt` в корне открытой папки.
> > 2. Подставляет путь к `.exe` выбранной цели запуска; благодаря `cmake.buildBeforeRun` перед этим цель собирается.
> > 3. Ошибка линковщика `LNK2005: main already defined`: два определения одного символа.
> > 4. `cout` отправляет в консоль байты UTF-8, а консоль читает их как CP866. `println` в консоли Windows перекодирует текст и выводит его через Unicode-функцию `WriteConsoleW`.
